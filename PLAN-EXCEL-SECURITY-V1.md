# Plan: Excel Sync Security V1 — secured pipes, business-only multi-user collab, role-unified permissions
_Locked via grill — by Claude + Isaiah, 2026-06-11. Revised after Codex round 1. PLAN_FILE deviates from root PLAN.md (governing Excel-sync contract, never overwritten by review loops)._

## Goal

Close the unauthenticated Excel side door and unify the permission model in one wave. Today, any change to a watched workbook is ingested client-side with no server validation of who made it. After V1: every Excel-originated change is validated AND applied server-side against the signed-in actor's role; each survey has exactly ONE live trusted workbook registered server-side; business cloud exports get per-email permissions stamped from effective document access (the active collaborator list); every Excel-origin write lands in an immutable audit journal; and in-app permissions flip to role-based (Editors + Owners can edit/delete everyone's markers, annotations, and regions) gated behind extending the 30-day trash to all annotation types. The Excel add-in (live sync for Dropbox/Google Drive/local without the app) is V2, built on these secured pipes.

## Approach

1. **Server-minted workbook registration (one-live-workbook registry).** At export, the client calls a new registration RPC; the SERVER mints `workbookId` + `syncToken` (secret generated and held server-side — Supabase Vault/secrets; DB stores only token hash + expiry + revocation flag). The token is embedded in the workbook's hidden metadata sheet. For business exports, registration also binds the Graph file identity (driveId + itemId) so a byte-copy of the workbook is distinguishable from the registered cloud file. Re-export retires the prior registration (token revoked). Retired/unknown workbooks cannot sync and surface "this copy is outdated — re-link or get the new file"; local-file copies (no Graph identity available) resolve via review/re-link only, never silent sync. Copied-workbook detection (Graph identity + eTag checks at submission) is best-effort POLICY hygiene, not a security wall against authorized editors — the actor-role check is the wall; full server-side Graph verification of file identity arrives with the server relay planned in the secret-rotation work. **Re-linking or replacing the live workbook is OWNER-ONLY** (with confirm + audit entry); editors see a "request re-link from the owner" path. The token binds workbook↔survey identity; it is NOT bearer authorization. Token rotation on share-list/role changes is OPERATIONALIZED, not just declared: rotation suspends sync, patches the new token into the cloud workbook in place (single-cell Graph write + readback verification, reusing the dormant Row-ID writer machinery); if the patch can't be verified, the workbook falls to the owner re-link flow; edits queued during suspension are preserved and resubmitted under the new token after re-validation.

2. **Server-side change-set validation AND application (transactional).** New Edge Function/RPC pair ingests row-level change sets carrying: `clientChangeSetId` (idempotency key), per-row op ids, `workbookId`, FULL row values + the client's base fingerprints per row (NOT client-computed field diffs — the server recomputes diffs itself against its stored state, trusting no client claims about what changed or what was deleted), and a monotonic per-workbook revision as a fast-path staleness check (per-row base-hash comparison remains the authoritative conflict test). The server validates: authenticated actor; editor/owner role on the document; active registered workbook (token hash match, not revoked, Graph identity match for business); freshness. Accepted rows are APPLIED by the server in the same transaction — annotation row write, `excel_sync_state` update, audit journal insert, revision bump — eliminating the validate-then-client-applies race. Unique constraints on (changeSetId) and per-row op ids make retries idempotent. Per-row outcomes return: applied / conflict(review) / stale / unauthorized. Validation logic ports the existing battle-tested pure-JS matcher/merge (`rowImportMatcher`, `buildScopeImportPlans`, `excelConflictDetect`) to the Edge runtime. PRECONDITION: the known paste-above matcher drift (open sign-off item in the scenario-coverage index) must be resolved and tested BEFORE the server port — we will not port a known-wrong matcher.

3. **Local-truth bridge (explicit V1 design, not an accident).** The live in-session truth for open documents is the collaborative doc engine; `document_annotations` is the synced store. V1 design: the server's transactional apply is authoritative for Excel-origin changes, and the server BROADCASTS each accepted change set (op ids + applied rows + new revision) on a realtime channel; ALL open clients — submitter included — apply from the server event, idempotently by op id (the submitter may apply from its direct response first; the event is a no-op repeat for it). No client is a single point of propagation. Missed-event recovery: clients track the per-workbook Excel revision; on reconnect or a detected gap they fetch and apply the missed accepted ops (not just at document open). Backstop: a reconciliation pass on document open compares the annotations store against the live doc and repairs any remaining divergence. This is a V1 bridge — the long-term home is the persistence rebuild's op-log/Yjs-authority work (KAL-263/KAL-270), and this design must not preclude it.

4. **Cloud-persisted Excel identity state.** New `excel_sync_state` TABLE (decided — not a JSONB column on annotations), keyed by (document_id, template_id, scope_id, marker_annotation_id, workbook_generation), holding fingerprints / assigned Row-ID token / writeback state / tombstone baselines so delete-grace and conflict checks work server-side and across devices. The renderer's localStorage copies become caches only. `excelSync` identity stamping on markers happens AFTER server outcomes return (sequencing amendment to PLAN.md Amendment (b), recorded at sign-off).

5. **Immutable Excel audit journal.** Excel-origin events (applies, edits, deletes, rejections, registrations, re-links) write to an append-only audit surface with NO delete policy for anyone — either a dedicated immutable table or a hardened event class in the history table with owner-DELETE removed for security events (final call at migration review). Each entry: actor id, workbookId, capability tier, change-set id, device hint, per-row outcome. The user-facing History panel reads from it for "who pushed what, when."

6. **Business-only multi-user gate, enforced from the registry.** Shared surveys (more than one collaborator) accept Excel-origin change sets ONLY when the REGISTRY says the active workbook is business-path (Graph identity bound at registration by an authorized editor/owner) — the server never trusts a per-request client capability claim. Local-file Excel sync remains available solely for UNSHARED surveys with an authenticated owner/editor actor — both conditions server-checkable; we make no claims about who is physically at the machine (the audit journal attributes every sync to the authenticated session). Viewer-actor change sets are rejected server-side regardless of path or token possession.

7. **Per-email cloud permission stamping (async with drift repair).** On business export: Graph sharing invitations per recipient — editors/owners write, viewers read, sign-in required. The desired-ACL source is EFFECTIVE document access (active document collaborators — the same source the server's access function uses), not a loosely-defined project share list. A desired-ACL record drives a stamping worker with retries; access changes enqueue re-stamps; a periodic drift scan repairs misses. The instant, guaranteed effect of unsharing someone is server-side: their sync grant and any token generation they hold are revoked immediately (cloud ACL removal follows within the worker's retry window).

8. **Viewer exports: locked + labeled + inert.** Viewer-initiated exports produce sheet-protected, clearly labeled read-only workbooks with NO registration — they can never sync. Sheet protection is a deterrent; the server rejection is the wall (a viewer holding even the live workbook's token is still rejected by the actor-role check).

9. **Local/owner-managed export warning.** Exporting to local disk or non-business storage shows: "Access to this Excel file is managed outside the app. Anyone you give the file to may edit it. Only authorized signed-in users can sync changes back."

10. **Trash/history/restore for ALL annotation types (gate for step 11).** Extends the markers' 30-day trash + History restore to shapes, ink, callouts, text, regions. Gets its own short design doc BEFORE build: per-type restore payload shape, retention, interaction with bulk delete and the collaborative doc, and tests — not a copy-paste of the marker mechanism.

11. **In-app permission flip across ALL write surfaces.** Role-based authority (editor/owner → full edit/delete on all content; viewer → none) applied consistently to: the client permission gate (`canModify`), the annotations-table RLS (author-match → role-based), the collaborative-doc update channel's server rules, AND the UI affordances (selection, context menus, bulk modes — the Phase-35 modal modes simplify). Ships only after step 10 is live, with role-matrix tests (owner/editor/viewer × edit/delete × own/others') at both client and RLS level.

12. **External-edit detection → review.** The local file watcher and Graph poll become detectors: any change arriving outside an authorized change-set submission, or from a non-active workbook, triggers the existing review flow (`pendingImportReview` + red icons) — never silent ingestion. PRECONDITION: the unplaced-rows review surface (KAL-292 — review entries with no marker row to attach to) ships BEFORE detector routing, so externally-added rows have somewhere visible to land.

13. **Test matrix (explicit, from Codex round 2).** Beyond per-slice unit tests: copied-workbook Graph-identity mismatch → review/re-link; token rotation patch + readback + queued-edit resubmission; ACL drift injection → worker repair; crash-between-accept-and-apply → open-time reconciliation repairs; legacy preflight snapshot → gate flip; role matrix (owner/editor/viewer × edit/delete × own/others') at client gate AND RLS AND collaborative channel.

## Key decisions & tradeoffs

- **Secure-pipes-first; add-in deferred to V2.** Server validation protects everything immediately; AppSource friction doesn't block security. Tradeoff: no live multi-user sync for Dropbox/Drive/local until V2 — accepted via the business-only gate.
- **Multi-user Excel collab restricted to M365 business storage in V1** — blockable because all ingestion passes the server gate and business registrations carry Graph-bound file identity.
- **One live workbook per survey**, server-registered, Graph-identity-bound for business. Copies and retired exports fall to review/re-link. Chosen for a clean trust story over multi-copy flexibility.
- **Server mints and holds token secrets** (Codex R1): client-held secrets can't be server-validated; DB stores hashes only.
- **Server applies what it validates, transactionally** (Codex R1): no validate-here/apply-there race; idempotent retries via change-set + op ids.
- **Full-row payloads; server recomputes diffs** (Codex R1): the server trusts no client claims about changed fields or deletions.
- **Roles stay owner / editor / viewer** (Isaiah's correction — "contributor" was a misnomer).
- **In-app flip rides in the same wave**, gated behind trash-for-all-types; flip covers client gate + RLS + collaborative channel + UI, not just one table.
- **Edge runtime reusing existing JS matcher** over a Postgres port — after the paste-above drift is fixed.
- **Owner's-unattended-machine residual risk accepted** — equivalent to an unlocked session; mitigated by per-session audit attribution, no device-level claims made.

## Risks / open questions

- **Latency on the import hot path:** server round-trip (cold starts included) before outcomes; mitigate by batching and a visible pending state; measure in the validation slice.
- **Local-truth bridge window:** crash between server accept and local doc apply leaves a gap until the open-time reconciliation; acceptable for V1, retired by the op-log rebuild (KAL-263/270).
- **Rate limits:** 5-second Graph poll + change sets must fit Supabase/Graph quotas; coalesce saves.
- **Amendment (b) sequencing change** (identity stamping after server outcome) recorded as a PLAN.md amendment at sign-off — owner-approved.
- **Paste-above matcher drift** must be fixed first (existing open sign-off item folds into this plan as a precondition).
- **Legacy workbook migration:** a PREFLIGHT (snapshot/quarantine of current linked-workbook state, per the root contract's backup-before-migration rule) runs before the V1 gate touches any existing linked document; then the gentle one-time re-export/re-link prompt.
- **Offline:** change sets queue durably and submit on reconnect; conflict odds rise — review flow covers.
- **Immutable-audit mechanism** (dedicated table vs hardened event class) — final call at migration review.

## Out of scope

- The Excel add-in itself, AppSource publishing, sideload tooling (V2 — nothing here may preclude it).
- xlwings in any form (rejected: Python runtime + licensing, no fit).
- Microsoft IRM / sensitivity labels (revisit only if customers confirm Business Premium licensing).
- A custom in-app spreadsheet grid (explicitly rejected — Excel stays).
- Personal-OneDrive live sync (stays disabled per standing veto).
- Viewer "add-only" rows (dropped — viewers request changes through the app).
- Excel-side row-level editor attribution (server trusts the authenticated syncing actor, not cell metadata).
- Full server-side Yjs authority (belongs to the persistence rebuild; V1 ships the bridge + reconciliation backstop).
