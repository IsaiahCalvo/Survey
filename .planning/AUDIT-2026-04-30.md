# End-to-End System Audit — 2026-04-30

Three deep-audit agents ran in parallel after the user expressed frustration
that "dumb mistakes that should have been obvious" keep slipping through.
This doc consolidates their findings and lays out the hardening backlog.

## The Repeating Pattern

Every bug we've shipped recently fits one of three shapes. Naming them so
future work can avoid them:

1. **Round-trip metadata loss.** Local object → cloud row → local object,
   and a field gets dropped somewhere in the middle. Today's silent-delete
   bug (page mutation reconstructed File without copying user_id). The
   highlight doubling bug (deserializer didn't stamp highlightId back onto
   the fabric object). The author-attribution flip on collaborator edit
   (serializer overwrites meta.authorId with the current user). Same
   shape, different field.

2. **Fail-closed gates with no boot guard.** A permission check returns
   false when an upstream value is null, instead of falling open OR
   waiting for the upstream to load. Today's silent-delete: documentOwnerId
   was null, canModify rejected everything, the bulk-delete planner
   returned no-op without telling the user. Pre-Phase-35, the same shape
   bit us with the sync queue gate when subscriptionTier hadn't loaded.

3. **State scoped globally that should be per-document or per-tab.**
   `documentSyncEnabled`, `pendingDeletePlan`, `lastSyncedAnnotationsRef`,
   `presenceCheckDocumentIdRef` — all live in App.jsx, none are reset
   when a tab closes. Tab A errored → flag flipped to false → tab B
   inherits the error state silently.

These three patterns explain ~80% of the bugs we've hit since v2.4 began.

## Top 10 Findings (Ranked by User Impact)

1. **Modals can fire against stale data after a tab close.** If the
   bulk-delete confirm modal is open and the user closes the tab, the
   modal stays mounted in App. Clicking confirm fires `runDelete` against
   a snapshot from the now-closed PDF. Wrong annotations get deleted on
   the wrong document.

2. **Closing a tab carries its sync error to the next PDF.**
   `documentSyncEnabled` is global. PDF A fails sync → flag flips false
   → user closes tab → opens PDF B → flag is still false → PDF B silently
   doesn't sync. User thinks "the new PDF is broken too." Actually it
   inherited tab A's error state.

3. **Local PDFs lose every annotation on close, no warning.** Drag a
   PDF in from disk (no cloud row), annotate for an hour, close the tab.
   Everything's gone. No "you have unsaved work" prompt. No
   localStorage queue. Mental model mismatch: nothing in the UI tells
   the user this PDF is local-only.

4. **Tier doesn't refresh mid-session.** User upgrades from free to pro
   in Stripe. App still enforces free limits until they re-focus the
   browser tab (which triggers a refetch). If they upgrade in-app and
   never blur, they're stuck on free tier features for the whole session.

5. **Storage orphans on failed inserts.** Upload to bucket succeeds,
   document insert fails (quota / network / RLS). File sits in cloud
   storage forever with no row pointing at it. No cleanup job. User's
   storage quota slowly leaks to garbage they can't see.

6. **Authorship flips on collaborator edit.** Annotation A is created
   by Alice. Bob (a collaborator) moves it 2px. Bob's edit re-serializes
   the annotation and stamps `last_modified_by = Bob` AND in the legacy
   path `user_id = Bob` overwriting Alice's authorship. Original-author
   tracking is broken.

7. **Concurrent edits silently last-write-wins.** Alice and Bob edit
   the same annotation in the same second. Both upserts hit Supabase.
   The second-arriving write overwrites the first. No conflict toast,
   no merge UI, no version field check. Alice's work disappears with
   no signal.

8. **Three competing sync paths keep diverging.** Highlights ride a
   legacy single-type path (`documentAnnotationService`). Everything
   else rides the new all-types path (`annotationCloudSync`). Phase 30
   added a CRDT dual-write fan-out on top of both. Any change to one
   path that doesn't get mirrored to the others causes parity bugs.
   Bug 2 (highlight partial-erase doesn't propagate) was exactly this:
   the legacy path didn't have delete-diff, the new path did.

9. **Permission checks are JS-only, no server-side RLS parity.**
   `canModify` runs purely on the client. Supabase RLS policies are
   separate. If they don't agree, a client-side "allowed" delete may
   bounce off RLS and silently fail. The undo toast doesn't fire on
   that failure either, so the user has no signal anything went wrong.

10. **Annotations drawn in the last 800ms before close are lost.**
    Sync writes are debounced 800ms. User draws → closes tab in 500ms
    → debounce timer is cleared on unmount → upsert never fires →
    annotation is gone. No localStorage queue, no `beforeunload` flush.

## Cross-Cutting Architecture Smells

- **Two sources of truth for the open document.** `selectedPDF` and
  `activeTab.file` can drift apart when `onUpdatePDFFile` skips
  non-active tabs.
- **clientSessionId is per-hook, not per-window.** Electron with two
  windows on the same Chromium process shares one session id → echo
  filter treats the other window's writes as "own session" and drops
  them. Two-window Electron is silently broken.
- **Test seams (`window.__phase35TestRoleOverride` etc.) depend on
  Vite tree-shake.** If a build slip ever leaves them in production,
  any user can self-elevate to owner by typing in DevTools.
- **`stroke_width` and `font_size` columns exist but no code populates
  them.** Future "find me all annotations with width > 10" queries
  can't index — they have to deserialize every row.
- **Storage uploads have no server-side size cap.** Client-side
  `canUploadDocument` check is the only barrier. A direct API call
  bypasses it.

## What This Audit Doesn't Cover

- Performance under heavy load (100+ pages, 1000+ annotations)
- Stripe webhook integration (entirely missing from this codebase)
- Mobile / iPad UX (separate work item)
- Server-side compute (Phase 28 RLS stubs, validators, etc.)

## Recommended Hardening Order

Pick one or two per session, not all at once. Each is low-risk,
test-coverable, and high-impact.

### Quick wins (1-2 hours each)
1. Reset `documentSyncEnabled` and ref-leaks on tab close.
2. Clear `pendingDeletePlan` when the active tab changes.
3. Add `beforeunload` warning when a local-only PDF has unsaved annotations.
4. Disable feature-gated buttons via the `disabled` attribute, not just opacity.

### Medium-effort hardening (half day each)
5. Refresh tier on document open + every 5 minutes, not just on focus.
6. Add a server-side cleanup job (cron) for storage blobs without document rows.
7. Flush the debounce timer in a `beforeunload` handler so the last 800ms doesn't get lost.
8. Stamp `meta.authorId` only on CREATE, never overwrite on edits — preserve original author.

### Bigger work (multi-session)
9. Migrate highlights onto the all-types sync path so the three paths collapse to one.
10. Add server-side RLS policies that mirror the client-side `canModify` chain.
11. Per-window session id for Electron multi-window.
12. Optimistic concurrency control on annotation upserts (version field + reject stale writes with a toast).

## How To Use This Doc

When you're about to add a feature:
- Will this feature add a new fail-closed gate? Add a boot guard.
- Will it add new state? Decide global vs per-document and reset it on tab close.
- Will it serialize to and from the cloud? Verify every field round-trips.
- Will it write to the documents or document_annotations tables? Check the
  schema for unpopulated columns and fill them.

When a bug report comes in, check this doc's pattern list first. Most bugs
fit one of the three shapes above.
