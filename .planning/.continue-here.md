**Open Issue 2 — Textbox resize handle drift DURING drag (user: "issue one is still persisting").**
User re-tested: when dragging a textbox resize handle, the bottom handles lift off the textbox's bottom border. The bottom three handles (bl, mb, br) are DRAMATICALLY lower than the text rect — not subpixel, visually obvious. Top/side handles look OK.

My hypothesis (STRONG but UNVERIFIED — we need logs before fixing):
- `src/components/SVGAnnotationLayer.jsx:633-641` (selection-overlay bbox during drag) computes `bbox.height = bbox.height / obj.scaleY * newScaleY`.
- `getTextBBox` for textbox returns `height = obj.height * scaleY + fontSize * 0.35` (descender buffer added AFTER scale).
- The inline resize math scales the descender buffer along with height — incorrect — so the handle bbox height diverges from the rendered text rect height, growing with drag distance. Explains "bottom handles expand faster."

Proposed fix (after logs confirm): replace the inline object at SVGAnnotationLayer.jsx:633-641 with:
```js
const transformedObj = { ...obj, scaleX: visualTransform.resize.scaleX, scaleY: visualTransform.resize.scaleY, left: visualTransform.resize.left, top: visualTransform.resize.top };
bbox = getAnnotationBBox(transformedObj);
```
This forces handle bbox and render math to use the same source of truth. Same fix likely applies to the imported-paths branch.

Also: my session-1 commit-time `measureTextBounds` re-tighten may have changed the wrong thing. Keep it for now and verify once the during-drag bug is fixed — it may be correct for POST-commit, just not for what the user was complaining about.

**Open Issue 3 — Shape edit handle offset when entering edit mode.**
User double-clicks a rect/circle, Fabric edit canvas mounts with opacity:0 shape + handles, SVG shape stays visible. User reports handles do not sit on the SVG rect's border — they land slightly inside/outside. Screenshot showed 5 arrows on mis-aligned handles.

Root cause unknown. Suspects:
- Stroke bleed: Fabric handles anchor to the object's logical bbox (left..left+width×scaleX), but the SVG rect's visible border extends `strokeWidth/2` outside that box. If strokeWidth=3, handles sit 1.5px inside visible border. (Probably too small to explain a "dramatic" visual offset, but log it.)
- Container CSS transform rounding in `buildBboxTransform` (FabricEditCanvas.jsx:74) — non-integer sub-pixel positioning.
- `effectiveScale` mismatch — container sized via parent offsetWidth/pageWidth; if parent has fractional dimensions, handles drift.
- The Fabric object's `scaleX/scaleY` are NOT reset to 1 in loadShapeAnnotation (unlike text), and buildBboxTransform uses `annWidth = obj.width * obj.scaleX`. If scaleX is non-trivial there could be a scale-squared or scale-halving artifact.

Do NOT guess-fix. Get logs, measure the delta in px, then fix.
