<open_issues>

**Open Issue 1 — Commit-path overflow + Edit-mode visual height snap. FULLY DIAGNOSED, NOT YET FIXED.**

User reproduced: after resizing a textbox to ~300×100, double-click to re-enter edit mode. The WIDTH stays correct (that's from fix #4 above). The HEIGHT visually snaps to tight-natural IN edit mode. When dismissed, the height pops back to 100 (the committed fix #5). User says: "we have to account for the vertical as well" and separately "overflow is not acceptable."

**Root cause A — Commit overflow (fix #5 is too blunt):**
- `FabricEditCanvas.jsx` commitAndClose unconditionally forces `json.height = originalAnnotationRef.current.height` for non-new textboxes.
- If user typed MORE text than fits the stored height, stored height is still forced → text overflows the visual bbox.

**Root cause B — Visual snap during edit (loadTextAnnotation never preserves stored height):**
- `FabricEditCanvas.jsx:869-880` re-edit path constructs `new fabric.Textbox(json.text, { ...rest, width: Math.max(json.width||0, 160), ... })` — **never passes `height`**. Fabric Textbox auto-computes `height = lineCount * lineHeight * fontSize` (tight natural).
- Line ~905: `actualH = textObj.calcTextHeight()` — natural.
- Lines ~910-913: `neededH = (actualH + padding) * es; canvas.setDimensions({ height: neededH })` — tight canvas.
- Lines ~929-930: `c.style.height = neededH + 'px'` — tight container div.
- Lines ~950-956 (`changed` handler): on every keystroke, container resizes from `calcTextHeight()` only, never checking stored height — same bug per-frame during typing.

So the stored `height=100` is ignored by both load-time sizing and per-keystroke sizing. During edit the user sees a tight box, then commit restores (or will restore) stored height → visual pop.

**Fix (exact, three spots, ~6 lines total, `FabricEditCanvas.jsx` only):**

All three spots apply the same `max(fabricNatural, storedOriginal)` rule.

1. **In commitAndClose** — replace the current unconditional restore block (the one I added this session for non-new textboxes) with:
   ```js
   if (!isNewText && activeObj.type === 'textbox' && originalAnnotationRef.current) {
     const naturalH = activeObj.calcTextHeight
       ? activeObj.calcTextHeight()
       : (activeObj.height || 0);
     const origH = originalAnnotationRef.current.height || 0;
     const origW = originalAnnotationRef.current.width || 0;
     // Width: honor user's chosen (wider) size; never shrink below what Fabric renders.
     json.width = Math.max(activeObj.width || 0, origW);
     // Height: grow with text, never shrink below user's chosen size.
     json.height = Math.max(naturalH, origH);
   }
   ```

2. **In loadTextAnnotation re-edit path (~line 905)** — after `textObj.initDimensions()`:
   ```js
   const naturalH = textObj.calcTextHeight
     ? textObj.calcTextHeight()
     : textObj.height * (textObj.scaleY || 1);
   const storedH = originalAnnotationRef.current?.height || 0;
   const actualH = Math.max(naturalH, storedH);
   // ... existing actualW line unchanged ...
   ```
   Then `neededH = Math.ceil((actualH + BBOX_PADDING * 2) * es);` already uses `actualH` — no further change.

3. **In the `changed` handler (~line 952)** — on every keystroke:
   ```js
   textObj.on('changed', () => {
     if (!mountedRef.current || !containerRef.current) return;
     const naturalH = textObj.calcTextHeight();
     const storedH = originalAnnotationRef.current?.height || 0;
     const effectiveH = Math.max(naturalH, storedH);
     const h = (effectiveH + BBOX_PADDING * 2) * es + 8;
     const newH = Math.max(Math.round(30 * es), Math.ceil(h));
     canvas.setDimensions({ height: newH });
     containerRef.current.style.height = newH + 'px';
   });
   ```

The Fabric Textbox object itself does NOT need its `height` property set — text renders from top-left. The container div holds the extra space at the bottom, which matches what the committed SVG will render via `getTextBBox` (`obj.height * scaleY + fontSize * 0.35`).

Width in loadTextAnnotation: the existing `width: Math.max(json.width || 0, 160)` line 880 already handles the width. User confirmed width works correctly. Don't touch it.
