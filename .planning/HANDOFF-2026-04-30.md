## What we shipped today — in plain language

Six things landed across versions 0.1.42 through 0.1.45. Some are bug fixes,
some are reliability hardening from the audit. Each one needs a quick check.

1. **0.1.42 — yellow highlight no longer shows up darker on the second device.**
   Before: draw yellow on Mac, open on Windows, the highlight looked darker
   like it had been stamped twice. After: it should look exactly the same on
   both machines.

2. **0.1.42 — partial erase of a highlight now reaches the other device.**
   Before: rub out half of a yellow highlight on one machine and the other
   machine still showed the full highlight. After: the erased half disappears
   on both.

3. **0.1.43 — marquee-and-delete works again on PDFs without ownership info.**
   Before: drag a selection box around some marks, press delete, nothing
   happens. After: the marks delete normally.

4. **0.1.44 — page edits no longer break delete-after.**
   Before: duplicate or delete a page, then try to delete an annotation,
   nothing happens. After: it works.

5. **0.1.44 — every fresh upload now records what computer it came from,
   your tier at that moment, and the build of the app.** Background metadata,
   not visible in the UI yet, but the migration must be applied to your
   Supabase project before the next upload (see "One thing to do before any
   upload" below).

6. **0.1.45 — five smaller hardening fixes from the audit.** Tier auto-
   refreshes every 5 minutes (a Stripe upgrade kicks in without reload),
   switching between PDFs no longer carries a sync error from the previous
   one, closing a tab with a local-only PDF that has marks shows a "leave
   site?" warning, the last second of marks before close gets one more shot
   at saving, and a teammate editing your mark doesn't overwrite your name
   as the original author.

## One thing to do BEFORE any upload

The last release added three new columns to the documents table — device,
user tier, and app version captured at upload time. The new code expects
those columns to exist. Open Supabase, go to the SQL editor, and run the
migration file `20260430000001_add_document_provenance.sql` from the
`supabase/migrations/` folder once. Three nullable columns get added; old
rows are unaffected. After that's done, fresh uploads stamp themselves
correctly.

If you skip this step, new uploads will fail with a "column does not exist"
error until you run it.

## The test plan — run one at a time, wait for confirmation between each

Each test has: the action, what you should see, and what to do if it fails.
Take a fresh save-log shortcut snapshot if anything looks wrong and hand the
folder back to the next-session Claude.

### Test 1 — yellow highlight no longer doubles on second device
- On Mac, open a shared PDF. Pick the yellow highlighter. Drag a yellow
  band across some text.
- Wait two seconds. On Windows, open the same PDF.
- The highlight should appear at the same shade you drew it. Not darker,
  not stamped twice.
- If it looks darker on Windows, hit your save-log shortcut on Windows
  and hand the folder over.

### Test 2 — partial erase reaches the other device
- Same setup. On Mac, pick the eraser tool. Swipe across half of the
  yellow highlight you drew in Test 1.
- The erased half should disappear on Mac immediately.
- Wait two seconds. Switch to Windows. The erased half should be gone
  there too.
- If the full highlight is still visible on Windows, save a log there.

### Test 3 — marquee delete now works
- On Mac, draw three or four pen marks anywhere on a page.
- Drag a selection box around all of them with the marquee tool.
- Press the Delete key.
- All selected marks should disappear immediately. An "Undo" toast
  should appear at the bottom for about six seconds.
- If nothing happens on Delete, save a log.

### Test 4 — page edit then delete still works
- On Mac, open a PDF. Right-click a page thumbnail and pick "Duplicate
  page" (or whatever page-edit option exists). Wait for the page to copy.
- Now draw a mark on any page. Click the mark, press Delete.
- The mark should disappear. (Before today, this would silently fail
  because the page edit dropped the document's identity info.)
- If delete fails, save a log.

### Test 5 — close-tab warning fires for local PDFs
- Drag a PDF in from your computer (not from the cloud dashboard —
  literally drag a file off your desktop into the app).
- Draw a couple of marks on it.
- Try to close the tab.
- The browser should pop up a generic "leave site?" prompt. Cancel that
  prompt, the tab should stay. Then close again, confirm the prompt,
  and the tab should close.
- If no prompt appears, save a log.

### Test 6 — author name survives a teammate edit (this is the 2nd-account one)
- Sign in to your DEVELOPER account on Mac. Open a PDF.
- Draw a square or pen mark. Make a note of who's listed as the author
  if there's any author label on it (or just remember "you drew this").
- Sign out of Mac. Sign in with the BRAND-NEW SECOND account on Mac.
- Click the square. Move it 50 pixels to the right. Click somewhere
  else to commit the move.
- Wait two seconds. Reload the PDF on Mac (still on the second account).
- The square should still be attributed to your developer account, not
  the second account. The "last edited" signal can be the second account.
- If the square now says it was authored by the second account, save a
  log.

### Test 7 — Pro tier kicks in within five minutes (only if you actually upgrade)
- Skip if you're not testing Stripe upgrades.
- If you ARE: sign in as a free user, leave the app open. In another
  browser tab, do a Stripe upgrade to Pro. Come back. Within five minutes,
  any feature that says "Pro only" should unlock without you reloading
  the app. The app polls itself every 5 minutes for tier updates.
