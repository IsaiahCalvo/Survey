# Phase 10 — UI Design Contract

> Visual and interaction contract for Canvas mount/unmount (pen, highlighter, eraser). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase nature:** This phase adds zero new UI chrome (no buttons, modals, forms, or layout components). It adds **Canvas overlay behavior** on existing PDF pages -- transparent drawing surfaces, cursor state machines, z-index layering, loading indicators, and SVG/Canvas visibility coordination. The design contract focuses on visual states, transitions, and interaction feedback rather than traditional spacing/typography/color systems.

## Canvas Overlay Visual Contract

This section replaces the standard color/spacing contract with the visual behavior contract specific to this phase.

### Layer Stack (z-index)

| Layer | z-index | Visibility by Tool | Description |
|-------|---------|-------------------|-------------|
| PDF page content (Syncfusion) | base | always visible | Rendered by Syncfusion viewer |
| SVG annotation layer wrapper | 100 | visible for pen/highlighter; `visibility: hidden` for eraser | Existing `<div>` wrapping `SVGAnnotationLayer` |
| Drawing Canvas (pen/highlighter) | 101 | visible when `activeTool === 'pen' \|\| activeTool === 'highlighter'` | Transparent Fabric.js Canvas, draws on top of SVG |
| Eraser Canvas | 101 | visible when `activeTool === 'eraser'` | Transparent Fabric.js Canvas with all annotations loaded |
| Eraser circle cursor | 99999 | visible when eraser active + pointer within viewport | Existing `position: fixed` cursor overlay |
| Region selection overlay | 1000 | when region selection active | Existing, unchanged |

**Source:** App.jsx line 24925 (SVG wrapper z-index: 100), App.jsx line 24193 (eraser cursor z-index: 99999), App.jsx line 24900 (region selection z-index: 1000).

**Rule:** Drawing Canvas and Eraser Canvas use z-index 101 to sit above the SVG layer (100) but below region selection (1000) and the eraser cursor (99999). Only one Canvas type is mounted at a time (pen/highlighter OR eraser, never both).

### Canvas Mount/Unmount States

| From State | To State | Trigger | Visual Transition | Duration |
|------------|----------|---------|-------------------|----------|
| SVG only | Drawing Canvas mounted | User selects pen or highlighter tool | Instant -- Canvas appears as transparent overlay, SVG stays visible underneath | 0ms (synchronous mount) |
| Drawing Canvas (pen) | Drawing Canvas (highlighter) | User switches pen to highlighter (or vice versa) | No mount/unmount -- brush config changes instantly | 0ms (no lifecycle change) |
| Drawing Canvas mounted | SVG only | User selects any non-drawing tool (select, pan, eraser, text, shape) | Canvas unmounts (dispose + DOM removal), SVG shows all committed strokes | 0ms (synchronous cleanup) |
| SVG only | Eraser Canvas mounted | User selects eraser tool | Cursor changes to `wait` immediately; SVG layer `visibility: hidden`; Canvas mounts and loads annotations; cursor changes to eraser disc when ready | 20-200ms (enlivenObjects load) |
| Eraser Canvas mounted | SVG only | User selects any non-eraser tool | Canvas unmounts, SVG layer `visibility: visible` with erased results already committed | 0ms (synchronous cleanup) |

### Canvas Element Positioning

```
/* Both FabricDrawingCanvas and FabricEraserCanvas wrapper div */
position: absolute;
top: 0;
left: 0;
width: 100%;
height: 100%;
pointer-events: auto;
z-index: 101;
```

**Canvas dimensions:** Container-aware measurement per CLAUDE.md rule. Measure `containerEl.offsetWidth / pageWidth` to get `effectiveScale`. Canvas logical dimensions set via `canvas.setZoom(effectiveScale)` with unscaled page coordinate space (`pageWidth x pageHeight`), so stroke coordinates are directly in SVG viewBox space.

### SVG Layer Visibility Toggle

| Active Tool | SVG Layer `visibility` | Reason |
|-------------|----------------------|--------|
| select | `visible` | Normal SVG interaction mode |
| text-select | `visible` | Normal SVG interaction mode |
| pen | `visible` | User sees existing annotations through transparent Canvas |
| highlighter | `visible` | User sees existing annotations through transparent Canvas |
| eraser | `hidden` | Eraser Canvas shows all annotations itself; hiding SVG prevents double-rendering artifacts |
| pan | `visible` | No Canvas mounted, SVG display only |
| shapes/text/line/arrow | `visible` | No Canvas mounted in Phase 10 (Phase 11 scope) |

## Cursor State Machine

| Tool Active | Canvas State | Cursor | Implementation |
|-------------|-------------|--------|----------------|
| pen | Drawing Canvas mounted, ready | `crosshair` | Fabric.js `canvas.defaultCursor = 'crosshair'` |
| pen | Mid-stroke (mouse down) | `crosshair` | Fabric.js handles during drawing mode |
| highlighter | Drawing Canvas mounted, ready | `crosshair` | Same as pen -- shared Canvas |
| eraser | Canvas mounting, annotations loading | `wait` | Set `cursor: 'wait'` on Canvas wrapper div until `enlivenObjects` callback fires |
| eraser | Canvas ready, pointer in viewport | `none` (native hidden) + custom circle overlay | Fabric.js `canvas.defaultCursor = 'none'`; existing eraser cursor div tracks pointer at `position: fixed; z-index: 99999` |
| eraser | Canvas ready, pointer outside viewport | `default` | Eraser circle hidden, native cursor restored |
| eraser | Mid-erase (mouse down) | `none` + circle overlay following pointer | Same as eraser ready -- circle follows continuously |
| select (after tool switch) | No Canvas | `default` | Canvas unmounted, SVG layer pointer events restored |

**Source:** PAL lines 4894-4898 (existing cursor logic), App.jsx lines 22507-22508 (eraser cursor hide), App.jsx lines 24179-24197 (eraser circle overlay).

### Eraser Circle Cursor Specification

| Property | Value | Source |
|----------|-------|--------|
| Shape | Circle (50% border-radius) | Existing App.jsx line 24189 |
| Diameter | `eraserSize * 2 * scale` pixels | Existing App.jsx line 24187 |
| Fill | `rgba(128, 128, 128, 0.2)` | Existing App.jsx line 24190 |
| Border | `max(1, 2 * scale)px solid rgba(100, 100, 100, 0.6)` | Existing App.jsx line 24191 |
| Positioning | `position: fixed; left: 0; top: 0` with `translate3d(clientX - radius, clientY - radius, 0)` | Existing App.jsx line 22140 |
| Pointer events | `none` | Must not intercept drawing events |
| GPU acceleration | `will-change: transform` | Existing App.jsx line 24194 |
| z-index | `99999` | Above everything |

**Decision:** Eraser cursor implementation is unchanged from existing App.jsx. Phase 10 reuses it as-is. The `FabricEraserCanvas` coordinates with the existing cursor by setting `canvas.defaultCursor = 'none'` and `canvas.hoverCursor = 'none'` and `canvas.moveCursor = 'none'`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | not applicable -- this phase has no buttons or CTAs; tool selection is via existing toolbar |
| Empty state heading | not applicable -- Canvas overlays always have spatial context (PDF page underneath) |
| Empty state body | not applicable |
| Error state (Canvas disposal failure) | Console error only: `"Canvas disposal error: {error}"` -- no user-facing error UI; Canvas is unmounted from DOM regardless |
| Error state (enlivenObjects failure) | Console error: `"Eraser annotation load failed: {error}"` -- Canvas remains mounted with empty state; user can switch tools to exit |
| Destructive confirmation | not applicable -- eraser operations are immediately undoable via Ctrl+Z (one erase = one undo step); no confirmation dialog needed |

**Rationale:** All error states are console-level because Canvas mount/unmount is an internal layer operation. The user's tool switching always works (unmount is synchronous). If annotation loading fails for eraser, the user sees an empty Canvas and can switch away -- no data is lost because nothing was committed.

## Interaction Feedback Contract

### Pen/Highlighter Drawing Feedback

| Moment | Visual Feedback |
|--------|----------------|
| Pen tool selected | Canvas mounts instantly (0ms); cursor becomes `crosshair`; user can start drawing immediately |
| Mouse down + drag | Live ink trail rendered by Fabric.js PencilBrush at 60fps on the upper canvas |
| Mouse up (stroke complete) | Fabric.js fires `path:created`; path is serialized and committed to SVG data; path remains on Canvas AND appears in SVG (overlapping perfectly); no visual change |
| Switch to select tool | Canvas unmounts; SVG layer shows all committed strokes; no visual gap because strokes were already committed per-stroke |
| Ctrl+Z while drawing | Last stroke removed from BOTH Canvas (via `canvas.remove(lastPath)`) and SVG data simultaneously; visual update is immediate on both layers |

### Highlighter-Specific Feedback

| Moment | Visual Feedback |
|--------|----------------|
| Highlighter tool selected | Same as pen -- Canvas mounts (or brush reconfigures if already mounted from pen) |
| Mid-stroke | Live `globalCompositeOperation: 'multiply'` blend on Canvas -- user sees realistic highlight effect against PDF content |
| Stroke complete | `globalCompositeOperation: 'multiply'` preserved in serialized JSON; SVG renderer applies `mix-blend-mode: multiply` |

### Eraser Feedback

| Moment | Visual Feedback |
|--------|----------------|
| Eraser tool selected | Cursor changes to `wait` immediately; SVG layer becomes `visibility: hidden`; Canvas mounts |
| Annotations loaded (20-200ms) | Cursor changes from `wait` to custom eraser circle; Canvas shows all page annotations (same visual as previous SVG display) |
| Mouse down + drag | Eraser circle follows pointer; erase path is being recorded |
| Mouse up (erase complete) | Boolean path subtraction applied via `geometryEraser.js`; modified annotations committed to SVG data; Canvas re-renders with erased result |
| Switch to non-eraser tool | Canvas unmounts; SVG layer becomes `visibility: visible` showing committed erased results |
| Ctrl+Z while erasing | Last erase operation reversed in BOTH Canvas and SVG; erased annotation restored |
