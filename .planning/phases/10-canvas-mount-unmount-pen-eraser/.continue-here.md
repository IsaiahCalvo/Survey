<decisions_made>

- Used `setPositionByOrigin(pathOffset, 'center', 'center')` instead of manual left/top computation — Fabric's internal method accounts for strokeWidth and scale in _getTransformedDimensions, which manual `pathOffset.x - width/2` misses by strokeWidth/2
- On erase commit serialization, normalize all path objects to left=0, top=0 — maintains SVG renderer compatibility (translate(0,0) is a no-op, path data renders at absolute coords)
- After _calcDimensions in erase, also call setPositionByOrigin with new pathOffset — keeps Canvas rendering correct for subsequent erase gestures
- Added ResizeObserver to FabricEraserCanvas (same as FabricDrawingCanvas) — Canvas must resize on zoom for annotation alignment
</decisions_made>

<context>
The eraser coordinate fix was the hardest problem — 3 iterations:
1. left=pathOffset.x, top=pathOffset.y → shifted down-right (too much offset)
2. left=pathOffset.x - width/2 → still shifted slightly (missed strokeWidth)
3. setPositionByOrigin(pathOffset, 'center', 'center') → correct (Fabric's own method)

Key insight: Fabric's _getTransformedDimensions includes strokeWidth in bounding box calculation, so manual offset math is always slightly wrong. Always use setPositionByOrigin for positioning paths.

The eraser zoom shift was a simple missing ResizeObserver — FabricDrawingCanvas had it but FabricEraserCanvas didn't.
