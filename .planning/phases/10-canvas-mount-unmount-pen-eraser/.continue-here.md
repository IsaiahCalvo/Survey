  - FIXED: Eraser single-use bug
    - Root cause: booleanErasePath in geometryEraser.js returned null for strokeWidth=0 objects.
      After first erase converts a stroke to filled outline (strokeWidth=0), all subsequent
      erases on that object returned null → object was skipped → nothing changed.
    - Fix: geometryEraser.js now treats strokeWidth=0 paths as filled polygons,
      using their path data directly as subject polygons for boolean subtraction.
    - Also fixed isConvertedToOutline return flag (only true when strokeWidth > 0)
      to prevent double-converting stroke→fill.
  - FIXED: Mid-stroke tool switch (deleted stroke instead of committing)
    - Root cause: useFabricCanvas cleanup ran first (canvas.off() unbinds all listeners),
      then FabricDrawingCanvas cleanup tried to flush via onMouseUp → path:created event
      was already unbound → stroke lost.
    - Fix: Added onBeforeDisposeRef callback to useFabricCanvas hook. Consumer sets a
      ref-based callback that runs BEFORE canvas.off()/dispose(). Both FabricDrawingCanvas
      and FabricEraserCanvas now flush via this callback.
  - FIXED: Zoom while drawing (erratic line)
    - Root cause: ResizeObserver resized canvas during zoom, changing viewport transform.
      Mouse:move events between resize and flush accumulated wrong coordinates.
    - Fix: ResizeObserver callback now flushes in-progress stroke BEFORE resizing canvas.
  - FIXED: Cursor not updating on tool switch
    - Root cause: CSS cursor only re-evaluates on pointer movement. Tool switch via keyboard
      left old cursor until mouse moved.
    - Fix: Added pointermove tracker + synthetic pointermove dispatch in activeTool useEffect.
  - FIXED: Cmd+Z/Ctrl+Z keyboard shortcut for undo not working
    - Root cause: No keydown handler for undo/redo shortcuts existed.
    - Fix: Added useEffect with keydown listener for Ctrl/Cmd+Z (undo) and Ctrl/Cmd+Shift+Z (redo).
      Uses handleUndoRef/handleRedoRef to avoid stale closures.

FIX THESE ONE AT A TIME — present each fix individually for user testing:

1. BUG: Eraser single-click — eraser only works on mousedown+drag, fails on single click
   - Root cause: mouse:up handler requires eraserPathRef.current.length >= 2 points.
     A click = mouse:down (1 point) + mouse:up (no move events = still 1 point) → skipped.
   - Fix: In applyEraserAndCommit, handle single-point eraser as a circle erase at that point.
     OR lower the minimum path length to 1 and treat single point as a dot erase.

2. BUG: Eraser precision — deletion radius is larger than the cursor circle
   - Root cause: eraserSize prop may not match the visual cursor overlay size, or
     booleanErasePath applies the radius in local space without matching visual scale.
   - Investigate: compare eraserSize value in FabricEraserCanvas vs the CSS overlay diameter
     in App.jsx (eraserSize * 2 * scale). The canvas eraser may not account for scale.

3. BUG: Mid-stroke tool switch — stroke commits but FLICKERS (disappears then reappears)
   - Root cause: onBeforeDisposeRef flush commits the stroke JSON, but the Canvas DOM is
     removed (unmount) before the SVG re-render picks it up. Brief frame with no visible stroke.
   - Fix: ensure SVG visibility is restored BEFORE or simultaneously with Canvas unmount.

4. BUG: Zoom while drawing — line stops but leaves a disconnected fragment when continuing
   - Root cause: ResizeObserver flush commits the stroke, then canvas resizes. The user continues
     drawing after resize, starting a NEW stroke (since the old one was committed). The gap between
     the committed stroke endpoint and the new stroke startpoint = disconnected fragment.
   - This may be acceptable behavior (stroke committed on zoom, new stroke starts fresh).
     Discuss with user whether this is OK or needs seamless continuation.

5. BUG: Cursor not updating on tool switch (pan/eraser) — still requires mouse movement
   - Root cause: The synthetic pointermove dispatch fix didn't work. Likely because
     dispatchEvent on the element doesn't cause the browser to re-evaluate CSS cursor.
   - Alternative fix: Instead of synthetic events, directly set cursor on the document.body
     or use a CSS class toggle that forces reflow.
