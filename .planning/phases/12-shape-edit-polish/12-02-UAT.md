### 1. Cold Start Smoke Test
expected: Kill any running dev server. Run `npm run dev` from scratch. Open http://localhost:5173/, load "Package 2 - Rev 4 -- IC.pdf", navigate to Page 6. The PDF viewer boots without console errors, the page renders, existing annotations appear, and selecting a rectangle shows the mtr rotation handle.
result: pass

### 2. Hover-intent pill appearance (AC #1)
expected: Select a rectangle on Page 6 (single-click for SVG select mode). Move the cursor onto the rotation (mtr) handle and hold it there for ~150ms. A small pill-shaped degree input appears 16px above the handle, displaying the current angle as an integer (e.g. "0" or "90") with a "°" suffix.
result: pass

### 3. Hover-leave grace period (AC #2/#3)
expected: With the pill visible from a hover, slowly move the cursor off the handle TOWARD the pill and reach the pill within 500ms — the pill stays visible and is clickable. Try again: leave the handle and DON'T move to the pill — after 500ms it fades out.
result: pass

### 4. Drag-start pill + live integer angle (AC #4)
expected: Click the rotation handle and start dragging to rotate the shape. The pill appears immediately (no 150ms delay) and its displayed value updates live to the integer-rounded current angle as you drag (e.g. 0 → 17 → 34 → 51 ...). Release — the pill stays at the final committed angle.
result: pass

### 5. Round 7 focus retention on mouseup (THE FIX — commit 82d80c3b)
expected: Hover the rotation handle until the pill appears. Click directly INTO the pill input (full mouse cycle: press AND release). Focus lands and stays in the input — the cursor is visible, ready for typing. Type a digit like "4". The character appears in the input and the input does NOT lose focus or get dismissed on the mouseup. (Before the Round 7 fix: clicking-and-releasing dismissed the pill on mouseup, focus was lost, typing impossible.)
result: pass

### 6. Enter commits typed value (AC #5)
expected: With the pill focused, clear the value and type "135", press Enter. The shape rotates to 135°, the pill loses focus, and the angle commits atomically. The displayed value normalizes to `[0, 360)` (typing "400" → commits "40", typing "-30" → commits "330" or similar normalized form).
result: issue
reported: "it performs the rotaiton but it isn't instant there is a slight delay. can we make it instant? as soon as the the user hits enter"
severity: minor

### 7. Escape cancels and reverts (AC #6)
expected: Note the shape's current angle (e.g. 135°). Click into the pill, type a different value (e.g. "200"), then press Escape. The pill loses focus, the shape reverts to its pre-edit angle (135°), and the typed value is discarded.
result: pass

### 8. Blur commits + invalid silently reverts (AC #7/#8)
expected: Type a valid number into the focused pill (e.g. "60") and click outside the pill (anywhere else on the page). The angle commits to 60°. Try again: type something invalid like "abc" or empty string, click outside — shape silently reverts to the pre-edit angle, no error popup.
result: skipped
reason: "User explicitly de-scoped this AC: 'no but thats fine, i dont want that' — blur-commit / invalid-revert behavior is not desired. Should be re-evaluated during 12-RECONCILIATION.md (AC may need removal from CONTEXT.md)."

### 9. Arrow Up/Down ±1° nudging (AC #9)
expected: With pill focused on a value like "90", press Arrow Up. Angle commits to 91° immediately (visible shape rotation). Press Arrow Down — back to 90°. Hold or repeatedly press to confirm each press is exactly ±1°.
result: issue
reported: "yes but there is lag we need this to be instant also it doesn't let me type letters or special characters into the input field, which is correct"
severity: minor
notes: "Arrow nudging increments correctly but with same visible lag as Test 6 Enter-commit. Likely same root cause (both go through the commit path). User also positively confirmed: input filter rejects letters/special chars at the source — this is correct behavior and partially covers AC #8 by preventing invalid input rather than reverting on blur."

### 10. Shift+Arrow ±45° nudging (AC #10)
expected: With pill focused on "90", press Shift+Arrow Up → angle commits to 135° immediately. Press Shift+Arrow Down → back to 90°. Each Shift+Arrow press is exactly ±45°.
result: pass

### 11. Snap NEVER applies to typed values (AC #11)
expected: With Shift held, click into the pill and type "44", press Enter. The committed angle is exactly 44° — NOT 45°. Snap is a drag-only gesture modifier, never a value filter on typed input. Verify by reading the pill display after commit.
result: pass
notes: "User observed that Shift+digit input was not accepted at all (likely because Shift+digit on US keyboards produces shifted chars '!@#$%^&*()' which the input's numeric filter rejects). User pragmatically marked this pass — 'I don't need to be holding shift and typing at the same time.' The AC is effectively unreachable via keyboard but also not a real workflow. Confirmed no accidental snap-to-45 behavior on typed commit."

### 12. Drag wins over typed value (AC #12)
expected: With the pill focused and a value like "60" typed but NOT yet committed, grab the rotation handle and start dragging. The drag's live integer-rounded angle overwrites the typed value in the pill display in real time. Releasing the drag commits the drag's final angle, not the previously-typed value.
result: pass

### 13. Constant-radius pill placement across rotations
expected: Select a shape and rotate it through 0°, 45°, 90°, 135°, 180°, 270°. At every rotation, the pill stays at a CONSTANT distance from the shape center — it never visually "breathes" closer or further as the shape spins. (Edge-to-edge gap may visually vary by angle, but the pill's orbit radius from shape center is invariant — this was the user-validated invariant from Round 2.)
result: pass

### 14. Position clamps to viewport at page edge (AC #13)
expected: Select a shape positioned near the top edge of the page, then either rotate so the mtr handle approaches the top of the viewport, or zoom out far enough that the handle is near the page edge. The pill clamps to stay on-screen — it never renders fully off-screen above/beside the viewport.
result: pass
notes: "Pill clamping works as specified. User flagged a RELATED UX gap captured as a separate feature request below — the rotation handle itself can go off-screen when a shape is rotated near the page edge, forcing the user to move the shape away before they can interact with the handle again. This is NEW scope, not an AC violation, and belongs in the v2.2+ backlog."
