# Phase 12 — UI Design Contract

> Visual and interaction contract for the Shape Edit Polish phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 12 ships three UI-touching changes on top of the v2.0 SVG display architecture:

1. **EDIT-11** — Soft Shift-snap to 45° during SVG shape rotation (zero new pixels; modifier-gated behavior change on an existing handle)
2. **EDIT-12** — NEW `RotationInputField` component: an HTML portal input that appears near the rotation handle for typed-angle commits (the only genuinely new UI surface in this phase)
3. **ZOOM-09** — Extend zoom floor from 50% to 10% (invisible behavioral change; no visual delta except that the existing zoom input will now accept `10`-`49`)

This contract is deliberately narrow: the only new rendered pixels in Phase 12 belong to `RotationInputField`. Everything else inherits the existing v2.0 look & feel.

## Interaction States

### `RotationInputField` visibility state machine (3 states)

| State | Enter condition | Exit condition | Visual |
|-------|----------------|----------------|--------|
| `hidden` | Default. Shape not selected, OR selected but no hover/drag. | mtr handle `pointerenter` for >150ms → `visible`. OR rotation drag starts → `visible` (immediate). | Not rendered. (Conditional render OR `opacity: 0` + `pointerEvents: none` — Claude's Discretion per CONTEXT.md, pick whichever minimizes flicker.) |
| `visible` | Hover-intent fired, drag started, OR cursor moved into the input from handle within grace period. | mtr handle `pointerleave` AND input not focused AND no active drag → start 500ms timer → `closing`. Rotation commit + input blur + no hover → `hidden`. | Full opacity, position tracks mtr handle screen rect, updated per `handlePointerMove` during drag. Focus border color: `#3A3A3A` unless `:focus-within`. |
| `closing` | 500ms grace timer running after leaving handle without entering input. | Cursor enters input OR input focused → cancel timer → `visible`. 500ms fires → `hidden`. | Identical to `visible` visually (NO fade animation mid-grace; grace is invisible to the user; only the final transition to `hidden` may fade). |

**Grace period is invisible:** During the `closing` state, the input looks identical to `visible`. The grace period exists so cursor travel from the handle to the input succeeds. Only when the 500ms expires does the input actually disappear.

**Drag overrides everything:** If a rotation drag is active, the input is `visible` regardless of any hover/blur state. When the drag ends, normal hover-intent resumes.

### `RotationInputField` focus state (2 states)

| State | Trigger | Visual | Keyboard bindings |
|-------|---------|--------|-------------------|
| unfocused | Default when visible. | Border `#3A3A3A`. Cursor not blinking. | None (input doesn't own keyboard) |
| focused | User clicks into the input, OR Tab-navigates in. | Border swaps to accent `#4A9EFF`. Cursor blinks. | Enter = commit typed value (normalized `[0,360)`), Escape = cancel + revert + blur, Blur = commit (Figma convention), ArrowUp/ArrowDown = ±1° commit immediately, Shift+ArrowUp/ArrowDown = ±45° commit immediately. All keyboard bindings scoped to the input — NO global `window` listeners. |

**Invalid input handling:** Non-numeric or empty string at commit/blur → silent revert to pre-edit angle. No red border, no toast, no aria-live announcement. This matches CONTEXT.md locked decision.

**Drag-vs-type conflict:** If the user is typing into the input (focus + uncommitted value) AND starts a drag on the mtr handle (via some other pointer path), the drag's live angle overwrites the typed value character-by-character in the input's displayed value. The user's partial typed state is effectively discarded. This is the "drag always wins" rule from CONTEXT.md.

### EDIT-11 Shift-snap interaction states

| User gesture | State | Committed angle |
|--------------|-------|-----------------|
| Drag mtr handle without Shift | free rotation | `newAngle` (float, normalized `[0, 360)`) |
| Drag mtr handle with Shift, within 3° of a 45° increment | soft-snap engaged | nearest 45° multiple, `% 360` wrapped |
| Drag mtr handle with Shift, >3° from any 45° increment | Shift ignored | `newAngle` (float, free) |
| Press Shift mid-drag without moving pointer | no visible change | next `pointermove` applies snap (convention-match) |
| Release Shift mid-drag | snap disengages | next `pointermove` is free |

**No visible snap indicator.** No tick mark animation, no highlight flash, no pulse. RESEARCH.md Pitfall "snap indicator animation" documented as anti-feature — zero surveyed annotation tools ship it.

### ZOOM-09 zoom floor states

No new visual states. The existing zoom UI (input field, toolbar buttons, scroll wheel, Cmd±, fit-page/width) behaves identically; the floor constant simply shifts. The zoom input displays `10` at minimum zoom; below 25% the selection handles remain rendered but are hard to target (accepted).

## Positioning Contract (EDIT-12 critical)

The rotation input's position is the only truly novel visual contract in Phase 12. This section is the authoritative spec.

**Anchor:** The visual center of the mtr handle `<g>` (rotation handle group) in `SVGSelectionOverlay.jsx`, resolved via `querySelector('[data-rotation-handle="mtr"]').getBoundingClientRect()`.

**Offset:** `16px` above the handle's top edge in screen pixels. The `16` value is from the 8-point scale (`md` token).

**Orientation:** Always upright in screen space. **Never rotates with the shape.** Even if the shape is at 135°, the input reads "135°" in horizontal text. Do not apply the selection overlay's `transform="rotate(angle, cx, cy)"` to the portal.

**Horizontal centering:** The input's horizontal center aligns with the mtr handle's horizontal center (`handleRect.left + handleRect.width / 2`), then clamped to the host div's width.

**Viewport clamping:**

```
left = clamp(4, hostRect.width - 60 - 4, computed_left)
top  = max(4, computed_top)
```

If clamping moves the input below the handle (`top > handle.top`), acceptable — the input will appear below the handle at extreme top-edge pages. No arrow/caret connector; the proximity is enough.

**Position recomputation frequency:**

- On every rotation `handlePointerMove` tick (drives the live "input follows handle as shape rotates" behavior)
- On hover-intent entering `visible` state (one-shot position)
- **NOT** on window resize, scroll, or zoom between rotation sessions — the handle rect is only stable during a single gesture, and between gestures the input is hidden anyway
- **Host div bounding rect is cached once per drag start** (per RESEARCH.md Pitfall 11 — avoid excess `getBoundingClientRect` calls during pointermove)

**Z-index stacking (Claude's Discretion per CONTEXT.md):** Recommend z-index `101` — one above the overlay div's `zIndex: 100` so the input sits visually above the SVG layer inside the same host div. Below Syncfusion's native page controls (which live at >1000 per the v2.0 portal architecture).

**Page-edge edge cases:**

- At 10% zoom with the mtr handle near the top edge of the PDF page, the input clamps to `top: 4`. Accepted.
- With the handle near the right edge, the input clamps to `left: hostRect.width - 64`. Accepted.
- With a shape in the extreme top-left corner and viewport clamping, input may visually overlap other selection handles. Accepted per CONTEXT.md ("zoom back in to edit if you need precision").

## Phase-Level Visual Parity Rules

These rules ensure Phase 12's new UI looks and feels native to the v2.0 app chrome — not like a bolt-on debug overlay.

1. **Container surface color MUST match MiniToolbar** — `#2D2D2D` background, `#3A3A3A` border, `borderRadius: 6`, `boxShadow: '0 4px 12px rgba(0,0,0,0.3)'`. If MiniToolbar ever changes these values, RotationInputField tracks it in a follow-up phase.
2. **Input value typography MUST match zoom input** — `fontSize: 13px`, `fontWeight: 500`, `letterSpacing: -0.2px`, `color: '#ddd'`, `textAlign: 'center'`, `outline: 'none'`.
3. **Suffix (°) typography MUST match zoom input's %** — `fontSize: 12px`, `fontWeight: 400`, `color: '#999'`, `pointerEvents: 'none'`, rendered as a sibling `<span>` (NOT part of the input's `value`).
4. **Font family MUST use the project-wide `FONT_FAMILY` constant** — do not hardcode a different stack. Import/re-declare the same 11-line stack from `App.jsx:116`.
5. **No drop shadow on the input itself** — only the container has the shadow. This avoids nested shadows that look heavy.
6. **No placeholder, no label, no hint text** — the input is always populated with the current angle when visible; contextual meaning comes from proximity to the rotation handle + the °-suffix.
7. **No icons inside the input** — no rotation icon, no lock icon, no chevron. The degree input is purely numeric.
