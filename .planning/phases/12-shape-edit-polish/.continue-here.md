<decisions_made>
- **Bug #2.6 root cause:** `viewer.getZoomValue()` LEADS the DOM re-layout.
  `magnification.zoomFactor` is undefined in this Syncfusion version. Three-way
  desync window: API=10%, DOM=88%, React=100% at failing moments. Any formula
  of the form `pageDiv / getZoomValue` is fundamentally broken during zoom in-flight.
- **Bug #2.6 fix pattern:** derive real page dimensions from pdf.js
  `pageSizes[pageNum]` (scale-invariant, PDF points) × one-time-calibrated
  Electron zoom factor. Never divide live pageDiv by getZoomValue. Calibrate
  opportunistically on first post-load scale change and re-calibrate on every
  MANUAL/FIT_WIDTH/FIT_PAGE/FIT_HEIGHT call from a known-commanded scale.
  Fallback factor=1.0 for first uncalibrated click is non-catastrophic and
  self-heals. User on Electron has factor ~1.33.
- **Syncfusion zoom family gotcha:** in Syncfusion mode, never call
  magnification.fitToPage/fitToWidth/fitToHeight. Always compute target scale
  from a trusted source (pdf.js points × calibrated factor) and call
  magnification.zoomTo() directly. Bugs #2 and #2.5 established the pattern;
  bug #2.6 refined it to use pdf.js as the trusted source instead of live DOM.
- Bug #2.5 v1 fix (gate effect on !useSyncfusionRenderer) was NOT the primary
  fix but is retained because it addresses a real secondary bug (stale
  ctrlMode causing 67→118% flash on fit-page click).
- Six+ App.jsx Always-Protected carve-outs justified in Plan 12-01 commit

Key generalized insight from bug #3 (add to CLAUDE.md gotchas next cleanup):
Fabric.js `strokeUniform: true` is NOT equivalent to SVG
`vector-effect="non-scaling-stroke"`. Fabric strokeUniform means "stroke
doesn't scale with object scaleX/scaleY during resize". SVG non-scaling-stroke
means "stroke pins to screen pixels regardless of ANY transform including
viewBox zoom". When an SVG renderer bakes scaleX/scaleY into coordinates
(like renderLine does), a plain strokeWidth already gives you Fabric
strokeUniform behavior for free. Adding non-scaling-stroke on top breaks
annotation-content strokes (they become disproportionately bold at low zoom).
Only use non-scaling-stroke for UI chrome strokes that should stay at fixed
screen pixels (selection bbox, handles).
</context>
