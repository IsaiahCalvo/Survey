Fix location (very likely): `src/hooks/useSVGInteraction.js` resize handler —
there's probably a `Math.max(minSize, ...)` or `Math.abs(...)` clamp on

edit-mode behavior which lets the shape flip.

While investigating, also check whether the onLivePreview path supports

User quote: "The mini bar doesn't stay fully centered over the shape.

Unclear root cause. Possibilities:
1. `positionStyle.left` = `toolbarPos.left + (toolbarPos.width - toolbarWidth) / 2`

in the toolbarPos state. Then positionStyle uses that as its center.

<graduated_insight>
**Dual-path Fabric-vs-SVG parity is a recurring gap.** Every default Fabric
option that affects shape-manipulation feel (uniformScaling, cornerSize,
uniScaleKey, minScaleLimit) must be explicitly overridden to match
useSVGInteraction.js behavior, or else double-clicking a shape silently
changes its interaction feel. Graduated to `feedback_ux_comments.md`:
every user-facing Fabric option / pointer-events / handle-sizing / threshold
must carry a code comment describing the intended UX, the reason, and the
reference behavior being matched.

**Canvas pixel-buffer math during scaling must account for obj drift.**
Fabric pins the opposite anchor during corner/edge scaling and drifts
obj.left/obj.top into the middle of the canvas. If canvas size is computed
from shape dimensions alone `(newW + BBOX_PADDING*2) * es`, the drifted
shape can exit the canvas pixel buffer and handles clip. Fix pattern:
`(max(BBOX_PADDING, o.left) + newW + BBOX_PADDING) * es` guarantees the
far edge always has padding regardless of drift direction.

**Mini-bar must track active-object top/left, not container.** During
in-flight vertical scaling, the container CSS position is static but the
shape's obj.top drifts. A container-rect-only tracker leaves the mini-bar
stranded. The rAF loop must read `fabricRef.getActiveObject()` every frame
and compute `(obj.top - BBOX_PADDING) * zoom` as a signed offset added to
`container.top`. DO NOT clamp the offset at zero: clamping creates a "wall"
where the mini-bar stops following upward scale. Bug #9 likely needs the
same treatment on the horizontal axis.
</graduated_insight>

  the SVG shape (via onLivePreview) is the visual truth. For corner-anchored

  handles already aligns with SVG pageLeft* es as long as the container CSS

  Reset only happens atomically at object:modified.
