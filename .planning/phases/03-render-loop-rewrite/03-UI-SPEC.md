## Scale Computation Contract

The `layerScale` value passed to all child components changes from a frozen/fallback chain to a live value:

| Property | Old Value | New Value |
|----------|-----------|-----------|
| `layerScale` | 20-line frozen/committed/measured/fallback chain | `syncfusionViewerScale > 0 ? syncfusionViewerScale : 1` |
| Freeze behavior | Scale frozen during zoom via `zoomFrozenBaseScale` | No freeze -- CSS transforms on overlay divs handle visual scaling |
| Fallback | `committedPageScale -> measuredPageScale -> frozenPageScale -> 1` | `1` (when `syncfusionViewerScale` is 0 or negative) |

**Visual impact:** During zoom transitions, the canvas will render at the current live scale while the CSS transform on the overlay div handles visual scaling. The combined effect is visually identical to the old frozen approach but without the scale-commit snap that caused flickering.

**Source:** CONTEXT.md locked decision -- "Strictly follow design spec: always use the current viewer scale, NO freezing"

## Ref Callback Contract

### Outer div ref (`syncfusionOverlayLayerRefs`)

```js
// KEEP -- simple tracking ref
ref={(node) => {
  if (node) {
    syncfusionOverlayLayerRefs.current[pageNumber] = node;
  } else {
    delete syncfusionOverlayLayerRefs.current[pageNumber];
  }
}}
```

### Inner content div ref (`syncfusionOverlayContentRefs`)

The 60-line complex ref callback (lines 24734-24791) containing transform reapplication, confirm-pending logic, and presentation mode sync is REPLACED with a simple tracking ref:

```js
// NEW -- simple tracking ref (old transform logic bypassed)
ref={(node) => {
  if (node) {
    syncfusionOverlayContentRefs.current[pageNumber] = node;
  } else {
    delete syncfusionOverlayContentRefs.current[pageNumber];
  }
}}
```

**Source:** RESEARCH.md Pitfall 6 -- "removing this callback is the correct action for the new path"
