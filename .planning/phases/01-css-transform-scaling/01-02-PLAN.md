```javascript
  left: number,
  top: number,
  width: number,

  scaleX: number,
  scaleY: number,
  stroke: string,
  fill: string,
  strokeWidth: number,
  opacity: number,
  angle: number,

  path: [['M', x, y], ['Q', cx, cy, ex, ey], ...],  // Fabric.js path commands
  // For line objects:
  x1: number, y1: number, x2: number, y2: number,
  // For group objects (arrows):
  objects: [{type: 'line', x1, y1, x2, y2}, {type: 'triangle', name: 'arrowHead', ...}],
}
```

Current rendering flow:
1. `objectPreviewBase` (useMemo) processes objects into preview data (bounds, stroke, fill, etc.)
2. `objectPreviews` (useMemo) scales preview data by `safeScale`
3. JSX renders each preview as a `<div>` with border/background/transform

The enhancement needs to:
- Detect path/line/group types during the `objectPreviewBase` generation
- Store additional type-specific data (path commands, line coords, group children)
- Render SVG elements instead of divs for these types in the JSX

**Step 1: Extend objectPreviewBase to capture type-specific data**

In the `objectPreviewBase` useMemo loop (around line 60-101), after computing the current preview object, add additional properties based on object type:

```javascript
// After the existing preview.push() properties...
const objectType = String(object.type || '').toLowerCase();

// For path objects (freehand/ink):
const isPath = objectType === 'path' && Array.isArray(object.path) && object.path.length > 0;

// For line objects:
const isLine = objectType === 'line';

// For group objects (arrows -- groups containing a line + triangle arrowhead):
const isGroup = objectType === 'group' && Array.isArray(object.objects) && object.objects.length > 0;
const lineChild = isGroup ? object.objects.find(o => o && (o.type === 'line' || o.type === 'polyline' || o.type === 'path')) : null;
const arrowHeadChild = isGroup ? object.objects.find(o => o && (o.name === 'arrowHead' || o.type === 'triangle')) : null;
const isArrow = isGroup && lineChild;
```

Add these fields to each preview object pushed to the array:
- `renderType`: `'path'` | `'line'` | `'arrow'` | `'shape'` (default for existing div rendering)
- For paths: `pathData` -- the raw Fabric.js path array converted to an SVG `d` attribute string
- For lines: `x1`, `y1`, `x2`, `y2` from the object
- For arrows: `lineX1`, `lineY1`, `lineX2`, `lineY2` from the line child, plus `hasArrowHead` boolean

**Path data conversion:** Convert Fabric.js path array to SVG d string:
```javascript
const pathD = object.path.map(seg => seg.join(' ')).join(' ');
```

**Step 2: Scale type-specific coordinates in objectPreviews**

In the `objectPreviews` useMemo (line 114-121), also scale the type-specific coordinates:
- Path data: Do NOT scale path coordinates here. The SVG element will be positioned at (left, top) and the path rendered with a `transform` using scaleX/scaleY.
- Lines: Scale `x1 * safeScale`, `y1 * safeScale`, etc.
- Arrows: Scale `lineX1 * safeScale`, etc.

**Step 3: Render SVG elements in JSX**

Replace the single `objectPreviews.map` rendering with type-aware rendering. For `renderType === 'shape'` (and text), keep the existing `<div>` rendering unchanged.

For `renderType === 'path'`:
```jsx
<svg
  key={preview.key}
  style={{
    position: 'absolute',
    left: 0,
    top: 0,
    width: overlayWidth,
    height: overlayHeight,
    pointerEvents: 'none',
    overflow: 'visible'
  }}
>
  <path
    d={preview.pathData}
    stroke={preview.stroke}
    strokeWidth={preview.strokeWidth}
    fill="none"
    opacity={preview.opacity}
    strokeLinecap="round"
    strokeLinejoin="round"
    transform={`translate(${preview.left}, ${preview.top}) scale(${safeScale})`}
  />
</svg>
```

Note: The path coordinates from Fabric.js are relative to the object's own coordinate system. The translate positions the path at the object's location, and scale adjusts for the overlay scale. The scaleX/scaleY from the object itself should be incorporated: `scale(${toNumber(object.scaleX, 1) * safeScale}, ${toNumber(object.scaleY, 1) * safeScale})`.

For `renderType === 'line'`:
```jsx
<svg
  key={preview.key}
  style={{
    position: 'absolute',
    left: 0,
    top: 0,
    width: overlayWidth,
    height: overlayHeight,
    pointerEvents: 'none',
    overflow: 'visible'
  }}
>
  <line
    x1={preview.x1}
    y1={preview.y1}
    x2={preview.x2}
    y2={preview.y2}
    stroke={preview.stroke}
    strokeWidth={preview.strokeWidth}
    opacity={preview.opacity}
    strokeLinecap="round"
  />
</svg>
```

Line coordinates: Fabric.js line objects store x1/y1/x2/y2 relative to the object center. The absolute endpoints are computed as:
```
absX1 = (left + x1) * safeScale
absY1 = (top + y1) * safeScale
absX2 = (left + x2) * safeScale
absY2 = (top + y2) * safeScale
```
where `left`/`top` are the object's `left`/`top` and `x1`/`y1`/`x2`/`y2` are the line's own coords. Adjust based on what the actual serialized data looks like at runtime -- if x1/y1/x2/y2 are already absolute, scale directly.

For `renderType === 'arrow'`:
```jsx
<svg
  key={preview.key}
  style={{
    position: 'absolute',
    left: 0,
    top: 0,
    width: overlayWidth,
    height: overlayHeight,
    pointerEvents: 'none',
    overflow: 'visible'
  }}
>
  <line
    x1={preview.lineX1}
    y1={preview.lineY1}
    x2={preview.lineX2}
    y2={preview.lineY2}
    stroke={preview.stroke}
    strokeWidth={preview.strokeWidth}
    opacity={preview.opacity}
    strokeLinecap="round"
  />
  {preview.hasArrowHead && (() => {
    // Calculate arrowhead direction from line endpoint
    const dx = preview.lineX2 - preview.lineX1;
    const dy = preview.lineY2 - preview.lineY1;
    const angle = Math.atan2(dy, dx) * (180 / Math.PI);
    const headSize = Math.max(6, preview.strokeWidth * 3);
    return (
      <polygon
        points={`0,${-headSize/2} ${headSize},0 0,${headSize/2}`}
        fill={preview.stroke}
        opacity={preview.opacity}
        transform={`translate(${preview.lineX2},${preview.lineY2}) rotate(${angle})`}
      />
    );
  })()}
</svg>
```

Arrow group coordinates: The group's `left`/`top` is the group center. The line child's x1/y1/x2/y2 are relative to the group center. Absolute coords:
```
absX = (groupLeft + childLeft + childX) * safeScale
```
Inspect actual serialized data at runtime to verify coordinate system. The research notes this needs runtime verification (Open Question #2).
