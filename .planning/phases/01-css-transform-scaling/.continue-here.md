<decisions_made>

- REJECTED iteration 3: Using `zoomCssScale` from useZoomState as CSS transform ratio — it was WORSE. The app-level `cssScale = appScale / renderedScale` doesn't perfectly match `canvas.getZoom()` (which is set from DOM-measured `layerScale`). The mismatch caused annotations to be at wrong scale/position.
- ADOPTED iteration 4: Three-pronged fix — hybrid guard, rAF-internal transform removal, synchronous renderAll
- KEY INSIGHT: `isZooming` (from useZoomState) turns off 140ms after the last app-level scale change. But for toolbar zoom (instant jump), the DOM-measured `layerScale` continues changing for several frames AFTER `isZooming` turns false. Each `layerScale` change triggered a canvas resize (setWidth/setHeight which blanks the canvas), causing the disappearing annotations.
- KEY INSIGHT: The CSS transform removal was happening OUTSIDE the rAF (synchronous in the useEffect), while canvas resize was INSIDE the rAF (deferred). This created a 1-frame gap where annotations showed at the wrong scale.
- KEY INSIGHT: `requestRenderAll()` defers paint to NEXT rAF. Combined with the resize in the current rAF, this left the canvas blank for 1 frame between resize and repaint.
</decisions_made>

<context>
The architecture:
- Syncfusion PDF Viewer renders pages, our custom PageAnnotationLayer (Fabric.js canvas) overlays annotations
- During zoom, Syncfusion re-renders pages — the `scale` prop to PAL changes continuously
- The ORIGINAL problem: `scale` changes trigger `canvas.setWidth/setHeight/setZoom/requestRenderAll` on every tick, which blanks the canvas momentarily → annotations disappear
- The FIX STRATEGY: when zooming, skip the expensive canvas resize and instead apply CSS `transform: scale(ratio)` to the Fabric.js wrapperEl for GPU-accelerated visual scaling. After zoom settles, do one final canvas resize.

Key files:
- `src/App.jsx` line 9117: `useZoomState(scale)` → provides `isZooming`, `cssScale`, `renderedScale`
- `src/App.jsx` line ~23400: `isZooming={isZooming}` prop passed to PAL
- `src/PageAnnotationLayer.jsx` line ~7643: The scale useEffect with CSS transform logic
- `src/hooks/useZoomState.js`: `isZooming = Math.abs(cssScale - 1) > 0.001`, debounce 140ms

The zoom flow:
1. User zooms → Syncfusion fires zoomChange → app `scale` state updates
2. `useZoomState(scale)` computes `isZooming=true`, `cssScale=newScale/renderedScale`
3. `layerScale` = DOM-measured page scale (via `measureSyncfusionPageScale`)
4. PAL receives `scale={layerScale}`, `isZooming={isZooming}`
5. PAL useEffect: if shouldDeferResize → CSS transform; else → canvas resize

The timing gap that causes issues:
- App `scale` changes instantly → `isZooming=true`
- `isZooming` turns false 140ms after last app scale change
- But `layerScale` (DOM-measured) keeps changing as Syncfusion settles
- Each `layerScale` change with `isZooming=false` → canvas resize → blank → disappearing!

Iteration 4's fix: `shouldDeferResize = isZooming || scaleJump > 0.05` covers the settling period by checking the ACTUAL scale difference, not just the `isZooming` flag.
</context>
