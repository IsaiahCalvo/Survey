<decisions_made>

**Prior sessions (preserved):**
- REVERTED full interaction system activation (rAF loop too expensive — 197 writes/tick)
- ADOPTED App-level synchronous CSS transforms (direct DOM writes in zoom handler)
- REMOVED PAL-level CSS transforms entirely (App handles via parent div)
- Settle timer 800ms → 300ms, useZoomState debounce 140ms → 60ms
- Double-rAF stagger queue for browser paint between Fabric renders
- Center-page-only immediate render, non-center deferred 2s

**This session:**
- REMOVED cumulative scroll correction — was producing 13K+ px drift, Syncfusion's default scroll is better for now. Cursor-centered zoom deferred to Phase 2 proper implementation.
- Trackpad vs ctrl+scroll distinction: trackpad sends ~4x more events (253 vs ~14 per session), causing 4x worse during-zoom performance. Root cause is event density, not the zoom math.
- 32ms throttle chosen (every other frame at 60fps = ~30 zoomTo/sec) — matches ctrl+scroll's natural event density
- inZoomModeRef must stay TRUE for non-center pages until their deferred render fires — clearing it early causes the scale effect's direct resize path to bypass the deferral
- pendingScaleRef must NOT be nulled in settle callback — only cleared in doRender(). Nulling it causes scaleActuallyChanged=true on re-renders, spawning cascading settle timers.
- User wants me to stop asking what to fix and instead use reasoning to pick highest-leverage fix in a momentum chain
</decisions_made>

<blockers>

- Interaction system (dual-layer overlay) is OFF — reverted because rAF loop overhead exceeded benefit.
- Non-center page deferred render differentiation may still have another bypass path (all pages clearing scaleMismatch simultaneously in logs).
