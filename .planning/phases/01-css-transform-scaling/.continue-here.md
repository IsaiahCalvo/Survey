<decisions_made>

- REVERTED `syncfusionViewerScale` as stable scale source: `getZoomValue()` reports the TARGET zoom before Syncfusion finishes rendering, causing CSS transform to overshoot the page's actual visual size. DOM measurement (`getSyncfusionPageScale` via `clientWidth/baseWidth`) is more accurate for tracking what the user sees, even though it can fluctuate.
- INCREASED settle timer to 800ms (from 500ms): Zoom-out scroll events have 300-900ms gaps. 500ms timer fired mid-gesture. 800ms covers most gaps. Added `isZoomingRef` guard as belt-and-suspenders — if zoom is still active when timer fires, reschedule instead of doing expensive resize.
- KEY DISCOVERY: `syncfusionInteractionPhase` never activates in default mode. The entire interaction management system (`markSyncfusionInteractionActive`, portal host freezing, container identity freezing, `isInteracting` prop) is gated behind `syncfusionLiveStableOverlayEnabled && syncfusionDualLayerEnabled`, which default to false. This means PAL's `isInteracting` is always false — the CSS transform during interaction fix and all portal/container freezing are inert.
- The zoom mode latch (`inZoomModeRef`) is the ONLY mechanism controlling zoom behavior in default mode. It enters on `isZooming || scaleJump > 0.01` and exits when the settle timer callback completes.
</decisions_made>

<blockers>
- FUNDAMENTAL: During zoom-out, Syncfusion's page re-rendering blocks the main thread for 300-800ms. CSS transform updates (scheduled via React effects) can't execute during this time. This causes annotations to lag behind the page during zoom-out, regardless of how clever the PAL-level logic is.
- The interaction system being inactive in default mode means portal hosts change freely during zoom, potentially causing PAL remounts. Activating the interaction system for zoom would be the cleanest fix but requires careful changes to `markSyncfusionInteractionActive` (removing the `liveStableOverlay` gate or adding a parallel activation path).
- Multiple PAL instances (one per visible page) each run their own settle timers. When timers fire simultaneously after zoom stops, multiple expensive resize+renderAll operations stack up, blocking the thread for N * (resize time).
</blockers>

<context>
Architecture:
- Syncfusion PDF Viewer renders pages in its own containers.
- PageAnnotationLayer (PAL) is a Fabric.js canvas portaled into each Syncfusion page container.
- During zoom, Syncfusion re-renders pages (resizing canvases). PAL needs to match.
- `useZoomState(scale)` in App.jsx produces `isZooming` (true when cssScale != 1, 140ms debounce).
- `layerScale` is computed per-page from DOM measurement (`getSyncfusionPageScale` = `clientWidth / baseWidth`).
- PAL receives `scale={layerScale}` and `isZooming={isZooming}`.
- PAL's scale useEffect: if `inZoomModeRef` is latched, apply CSS transform + defer resize via settle timer. Otherwise, direct resize via rAF.
