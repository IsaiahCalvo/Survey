<completed_work>

**Core CSS transform scaling (working):**
- App-level synchronous CSS transforms during zoom (GPU-accelerated)
- 3-tier page priority system: center (immediate render), visible (800ms delay), off-screen (IntersectionObserver)
- Double-rAF stagger queue for browser paint between Fabric renders
- Smart settle timer (300ms, only resets on actual scale change)
- inZoomModeRef latch with correct clearing (only in doRender, not settle callback)
- pendingScaleRef preserved through settle (prevents cascading timers)

**This session — tested and reverted:**
1. Trackpad 32ms throttle: REVERTED — made jank worse (2.20 → 3.50/gesture). Fewer, larger zoom jumps cause heavier Syncfusion processing.
2. Center-page threshold 0.6→0.25: REVERTED — no measurable effect. scaleMismatch metric tracks App CSS transform, not per-page canvas state.
3. Non-center pages through stagger queue at 1500ms: REVERTED — created second jank wave worse than original.
4. requestIdleCallback for render queue: REVERTED — batched all renders into one idle block with no paint cycles, worst result (6.83/gesture).
5. Settle timer 300ms→500ms: REVERTED — didn't help, Syncfusion jank dominates regardless.
6. App safety timer 1000ms→500ms: REVERTED — no measurable benefit.
7. Multiplicative zoom formula, zoom input tracking, bridge skip: REVERTED — accumulated App.jsx changes contributed to regression.

**Key finding: all 175 lines of App.jsx changes from committed state contributed to regression from 2.09 to 3.92. Only the byte-identical committed code achieves 2.09.**
</completed_work>
