<decisions_made>

- REVERTED full interaction system activation: The overlay transform loop (rAF-based DOM measurement + style writes for all pages every frame) caused MORE overhead than it saved. Worst frame went from 1312ms to 4273ms.
- ADOPTED App-level synchronous CSS transforms: Applied directly in `handleSyncfusionZoomChange` callback, before React processes state updates. Zero React overhead — just direct DOM style writes to overlay content divs.
- REMOVED PAL-level CSS transforms entirely: App handles visual scaling via parent div transform. PAL only defers its expensive canvas resize. Prevents double-transform compounding issue (parent + child transforms).
- Base scale captured from `scaleRef.current` BEFORE updating it (prevScale): Ensures CSS transform ratio is relative to what the canvas was actually rendered at, not the zoom target.
- Safety timer set to 2000ms (vs PAL's 800ms): Primary cleanup is via `handlePALScaleApplied` callback. Safety timer is just a fallback for error cases.
- Staggered resize queue: Module-level shared queue across all PAL instances. One resize per `requestAnimationFrame`. Guards against stale callbacks via `inZoomModeRef` check. `inZoomModeRef` cleared before enqueueing so queued callbacks can run, but re-latched if new zoom starts.
</decisions_made>

<blockers>
- Syncfusion's page re-rendering still blocks main thread for 300-800ms during zoom-out steps. The App-level CSS transform compensates visually, but the underlying thread-blocking remains. This is a Syncfusion limitation we can't fix.
- Post-zoom Fabric.js `renderAll()` is expensive (~300ms per page). Stagger queue spreads this across frames but total time is the same.
</blockers>
