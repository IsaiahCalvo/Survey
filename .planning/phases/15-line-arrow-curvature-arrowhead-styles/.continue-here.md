## Plan 15-04 Step 3 — Live-sync Fabric typing into the SVG

**The gap**: during edit, the SVG shows the STALE pre-edit text. As user types, Fabric's internal state updates, but the SVG doesn't refresh. Commit path restores, so the final saved annotation is correct — but during edit, user sees old text + blinking cursor, which is confusing on existing annotations and completely unusable for new text creation (no SVG to show).

**Approach**: on every Fabric `text:changed` event, push the new text value (and optionally pre-wrapped lines from `textObj._textLines`) through a React prop bridge so the SVG renderer re-paints with live content.

**Existing infrastructure to leverage**:
- `onLiveTextGrow` callback prop on FabricEditCanvas (already wired) — currently emits bounds on every `text:changed`. Extend to also carry `text` string + `textLines` array.
- `liveCalloutEditBounds` state in `App.jsx` (already plumbed through 3 SVG render sites) — extend to `liveCalloutEditData` (bounds + text + lines).
- For plain textbox (non-callout) edit, a parallel `liveTextEditData` state may be needed.

**Files to touch** (expected):
- `src/components/FabricEditCanvas.jsx` — `text:changed` handler at ~line 1593; extend payload.
- `src/App.jsx` — state wire.
- `src/components/SVGAnnotationLayer.jsx` — forward new prop.
- `src/utils/svgAnnotationRenderers.jsx` — `renderText` + `renderCallout` accept optional live text and prefer it over stored text when present.

**Two sub-options for the renderer**:
1. Simplest: replace `obj.text` with live text string, let `<foreignObject>` CSS wrap as before. Fixes visible-text drift. May not fix Bug A (wrap parity between Fabric and CSS) if user types near a wrap boundary.
2. Bigger: use `textObj._textLines` (Fabric's wrapped array) as `<tspan>` lines inside an SVG `<text>`. Both layers wrap identically. Solves Bug A + Bug C together.

Recommend Option 2 for a one-shot fix. Risk: `<text>` + `<tspan>` position math is different from `<foreignObject>` positioning — needs line-by-line `dy` stepping.

**Watch-outs**:
- New text creation path still has NO SVG underneath (Fabric is the only visual until commit). Either (a) render SVG preview from Fabric live text in the edit renderer, or (b) keep Fabric visible for new-text-creation only — flip the transparent fill to a real color only when `isNewText=true`.
- Mini-toolbar fill change during edit is NOT preserved by current `commitAndClose` restore — out of scope for Step 3, but log as a known drift if user reports it.
- The three `[CALLOUT-DIAG]` logs are still planted and still useful for Step 3 debugging. Keep them until Step 3 ships; remove in the final commit that closes Plan 15-04.
