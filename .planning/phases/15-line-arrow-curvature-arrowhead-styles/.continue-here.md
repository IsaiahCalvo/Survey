**User is right.** The 5-object composite (`line1 + line2 + rect + tipDot + textbox`) over-models the callout. The cleaner data model is `{ textbox + line + arrow }` — the textbox IS the visible box (its own `stroke`, `fill`, `width`, `height`), same as regular text annotations.

**Architectural simplification — drop the rect child, make textbox IS-the-box:**

1. **Data model change:** React callout stops needing a separate rect. `textBoxPosition + textBoxWidth + textBoxHeight` are inferred from the textbox object itself.

2. **`src/utils/calloutEditAdapter.js`:**
   - `toFabricGroup` — emit 4 objects instead of 5: `[line1, line2, textbox, tipDot]`. Textbox carries its own `stroke`, `strokeWidth`, `fill`, `rx`, `ry`, `strokeUniform`, `borderColor: transparent`, etc. Drop the rect child entirely.

<context>
**Mental model that should inform next session:**

A "text callout" is *literally*:
- One textbox (the content + the visible border/fill)
- One line from the textbox edge to a knee point
- One line from the knee to the arrow tip
- One arrowhead at the tip

That's 4 things, not 5. The rect child we have today is a historical artifact from when the callout was imagined as a Fabric.js `Group` with explicit sub-shapes. In the SVG-unified world, a single textbox object with its own `stroke`/`fill`/`rx`/`ry` attributes renders identically to what the rect was providing — and it's the same object being edited, so there's no disconnect.

The text annotation (`renderText` + `FabricTextCanvas`) is the template. Copy its shape. The `stroke: '#000000', strokeWidth: 1, strokeUniform: true` default I already added in FabricEditCanvas.jsx for new textboxes lines up perfectly — callouts would re-use that exact rendering, just with an attached line + arrow.
