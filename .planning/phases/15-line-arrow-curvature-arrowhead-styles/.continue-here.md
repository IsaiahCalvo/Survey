## Plan 15-04 Issue 1 — Caret drift + wrap divergence ✓ CLOSED

Shipped as `f9c9a334 fix(svg): align SVG text/callout wrap + line-height to Fabric`.

**Two-rulers root cause confirmed via MAX-depth diag capture:**

1. **Line-height ruler** — CSS unitless `1.16` ≠ Fabric's
   `fontSize × lineHeight × _fontSizeMult (1.13)`. Caret drifted down
   ~2.88 px per wrapped line (textbox) / 2.21 px per line (callout).
   Ratio was exactly `_fontSizeMult = 1.1333`. Fix: multiply unitless
   line-height by 1.13 in both `renderText` and `renderCallout`.

2. **Wrap ruler** — Fabric's `splitByGrapheme: true` breaks at any
   character, browser's `word-wrap: break-word` prefers word boundaries
   and only breaks mid-word on overflow. Punctuation-heavy jamming
   produced 30 SVG visual lines vs 23 Fabric lines — extra lines
   overflowed the border. Also explained the "cursor jumped to middle"
   Option+Arrow word-jump confusion. Fix: add `word-break: break-all`
   to both inner divs.

**User-confirmed working** (2026-04-17 ~18:45): "It's fixed in text
boxes" → "seems fixed" after callout + wrap patches.

**Diag logs removed** in the same commit.

## Issue 2 — New-creation shows Fabric, not SVG (NOT YET STARTED)

**Symptom (user words, from previous session):** "When I first created
the text box, it looks like it's showing the fabric.js rather than
first showing the SVG. When I go into imported text boxes, I never see
fabric.js. Shapes are doing the same thing — when I first create the
shape, I see the fabric JS shape being created, and then once I commit
it, it changes to SVG and I can visibly see that."

**Root cause:** The new-text creation path at
`src/components/FabricEditCanvas.jsx:~1372-1402` sets `fill:
strokeColor` + `stroke: '#000000'` (opaque) because there's no SVG
annotation yet for Fabric to sit invisibly under. Same for shape
creation (presumably in `FabricDrawingCanvas.jsx` or the creation-tool
surface).

**Fix approach (no logs needed — structural):**
1. During creation, mount a **preview SVG annotation** that renders
   from the in-flight Fabric state (same `liveTextEditBounds` bridge,
   but seeded from create-drag state).
2. Make Fabric's new-text textbox transparent (fill + stroke
   `rgba(0,0,0,0)`) same as existing-text path at `FabricEditCanvas
   .jsx:1525-1526`.
3. On commit, the preview becomes the real annotation. No visible swap.

**Files expected to touch:**
- `src/components/FabricEditCanvas.jsx` — new-text branch's
  fill/stroke.
- `src/App.jsx` — new creation-preview state + feed it into
  `SVGAnnotationLayer` as an extra ephemeral annotation OR extend
  `liveTextEditBounds` to carry a "create mode" flag.
- `src/components/SVGAnnotationLayer.jsx` — render the preview.
- For SHAPES: same pattern in the shape-create path
  (`FabricDrawingCanvas.jsx` shape-creation tools, currently mounting
  Fabric as the only visible layer during drag).

**Watch-out:** Shape creation uses `FabricDrawingCanvas` which has a
different lifecycle than `FabricEditCanvas`. May need a separate bridge
or a shared "in-flight annotation preview" mechanism that both feed.
Worth scoping before coding.
