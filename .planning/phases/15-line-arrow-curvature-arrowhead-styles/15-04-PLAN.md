# Plan 15-04 — Text & Callout Edit Parity with Shapes

## Why

Bug A (text overflows the SVG box after commit) and Bug C (text/callouts visibly grow on edit-enter while shapes stay still) share one root cause: shapes keep the SVG as the "visual truth" during edit and mount Fabric invisibly on top; text and callouts do the opposite — SVG hides, Fabric renders. Fabric's Canvas 2D text metrics and the browser's CSS text wrapping disagree on sub-pixel widths and line breaks, so the swap causes the visible jump and the post-commit overflow.

## Approach

Extend the shape pattern to text and callout:

1. Keep SVG visible during text/callout edit.
2. Make the Fabric textbox visually transparent (text fill + border transparent) during edit — it still owns the caret, the hidden textarea, and the keyboard input. User sees only the SVG text + a native caret overlay.
3. On every Fabric `text:changed` event, push the pre-wrapped line array (`textObj._textLines`) + new width/height to the SVG renderer.
4. Replace the SVG `<foreignObject>` CSS-wrapping branch during edit with pre-wrapped `<tspan>` lines driven by Fabric's measurements. Wrap parity guaranteed because both layers now use Fabric's measurements.

## Acceptance Criteria

- **Given** the text tool, **when** I drag a new textbox and start typing, **then** the SVG box position does not jump and the SVG text appears letter-by-letter without a visible Fabric overlay growing beside it.
- **Given** a long paragraph in a textbox or callout, **when** I dismiss the edit, **then** the committed SVG text does not overflow the committed box by any pixels.
- **Given** I'm editing a callout, **when** text grows and wraps to a new line, **then** the connector line's anchor point tracks the box bottom live (already working from Fix 2 — must not regress).
- **Given** a rect / circle / ellipse / triangle, **when** I edit, **then** behavior is unchanged (regression guard).

## DO NOT CHANGE

- `src/App.jsx` — only the 3 existing `onLiveTextGrow` wire sites + 3 `liveCalloutEditBounds` sites get extended to carry line arrays. No new top-level state surface.
- `src/components/PageAnnotationLayer.jsx` — out of scope.
- `src/components/FabricDrawingCanvas.jsx` / `FabricEraserCanvas.jsx` — out of scope.
- `package.json` / `vite.config.js` — no infra changes.

## Tasks

### Task 1 — Extend live-text bridge to carry line array
Plumb `textLines` + `width` + `height` through the existing `onLiveTextGrow` → `liveCalloutEditBounds` flow. Add a parallel `liveTextEditBounds` for plain textbox edits (currently only callouts use the bridge). Files: `src/App.jsx` (state + wires), `src/components/FabricEditCanvas.jsx` (bounds payload extension), `src/components/SVGAnnotationLayer.jsx` (prop forwarding).

### Task 2 — Keep SVG visible during text/callout edit
Change `hideForEdit` logic in `SVGAnnotationLayer.jsx:~1549-1556` to also whitelist textbox + callout. The SVG becomes the visual truth. Keep `pointerEvents: 'none'` so clicks still pass to Fabric.

### Task 3 — Render pre-wrapped tspans in edit mode
In `svgAnnotationRenderers.jsx`, add an edit-mode branch to `renderText` + `renderCallout` that, when a `liveTextBounds` / `liveCalloutEditBounds` is passed, renders `<text>` with one `<tspan x=... dy=...>` per line from `bounds.textLines` instead of the `<foreignObject>` CSS branch. Non-edit paint path is unchanged.

### Task 4 — Make Fabric textbox invisible during edit
In `FabricEditCanvas.jsx` text + callout load paths: set text `fill: transparent`, `stroke: transparent`, `borderColor: transparent`, `editingBorderColor: 'transparent'`. Keep `cursorColor` opaque so the caret still shows. Keep `backgroundColor: transparent`.

### Task 5 — Commit path: persist the Fabric-measured wrap
On commit, write the final `_textLines` (or a reconstructed `text` string that will re-wrap identically in the CSS renderer) to the stored annotation. Non-edit display keeps using `foreignObject` but with Fabric-measured width so CSS wrap matches the edit-time wrap. If CSS still disagrees, fall back to persisting the `tspan` line array.

### Task 6 — Smoke test
Manual UAT: create textbox, type past wrap point, dismiss. Re-enter edit, confirm no visible jump, confirm committed text does not overflow. Same flow for callout.

## Risk / Fallback

If CSS wrap parity can't be achieved at commit time even with Fabric-measured width, fall back to persisting the `tspan` array in the annotation data and using it in the non-edit render path too. Cost: annotation JSON grows by ~N strings per text box. Acceptable.
