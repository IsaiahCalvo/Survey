Create the zoom-flicker scenario as a Playwright test file. This is the primary scenario for debugging the post-zoom flicker bug.

**Environment variable parameters** (FOUN-07):
```javascript
const ZOOM_MIN = Number(process.env.ZOOM_MIN || 100);
const ZOOM_MAX = Number(process.env.ZOOM_MAX || 200);
const ZOOM_STEP = Number(process.env.ZOOM_STEP || 25);
const START_PAGE = Number(process.env.START_PAGE || 6);
```

**Test structure:**
```javascript
import { test, expect } from '@playwright/test';
import { CaptureContext } from '../lib/capture.mjs';
import path from 'node:path';
```

**Module-level state** for video handling:
- `let ctx = null;` (CaptureContext instance, accessible in afterEach)

**test.afterEach hook** for video lifecycle:
- If `page.video()` exists, call `await page.video().saveAs(path.join(ctx.getSessionDir(), 'recording.webm'))`. This MUST happen in afterEach because Playwright finalizes the video file only after the page/context closes. saveAs() waits for completion automatically.

**Main test: 'zoom-flicker scenario':**

1. **Initialize capture:**
   - `ctx = new CaptureContext('zoom-flicker', page);`
   - `await ctx.start();` (records captureStartMs, starts console/perf capture, takes baseline screenshot)

2. **Navigate to test page:**
   - `await page.goto('/?testPdf=Package%202%20-%20Rev%204%20--%20IC.pdf');`
   - Wait for viewer: `await page.locator('.e-pv-viewer-container').waitFor({ state: 'visible', timeout: 60_000 });`
   - Wait for debug bridge: `await page.waitForFunction(() => window.__debugBridge != null, { timeout: 30_000 });`
   - Wait for PDF loaded: `await page.evaluate(() => window.__debugReady.waitFor('pdfLoaded', { timeout: 30000 }));`

3. **Navigate to START_PAGE** (if not page 1):
   - Use the established pattern: `page.getByRole('textbox', { name: 'Current page' })`, click, fill, press Enter.
   - Wait for readiness: `await page.evaluate(() => window.__debugReady.waitFor('ready', { timeout: 30000 }));`

4. **Zoom sequence** -- the core of the scenario:
   - Build zoom levels array from ZOOM_MIN to ZOOM_MAX in ZOOM_STEP increments. Example with defaults: [100, 125, 150, 175, 200].
   - For each zoom level, use `ctx.step()`:
     ```javascript
     await ctx.step(`zoom-${zoomLevel}pct`, async () => {
       await page.evaluate((level) => {
         // Access the Syncfusion PDF viewer instance and set zoom
         const viewer = document.querySelector('.e-pv-viewer-container');
         if (viewer?.ej2_instances?.[0]) {
           viewer.ej2_instances[0].magnification.zoomTo(level);
         }
       }, zoomLevel);
     });
     ```
   - The `ctx.step()` call handles: before screenshot, state capture, action execution, waitFor('ready'), after screenshot.

5. **Optional zoom back down** (reverse sequence):
   - Build reverse array from ZOOM_MAX back to ZOOM_MIN.
   - Same ctx.step() pattern for each level.

6. **Pass/fail determination** (CAPT-05):
   - After zoom sequence completes, evaluate criteria:
     ```javascript
     const finalSnap = await page.evaluate(() => window.__debugBridge.snapshot());
     const consoleErrors = []; // Collected from page.on('console') -- check if any errors occurred
     ```
   - Criteria:
     - `canvasContainerCount >= 1` (annotations still visible after zoom cycle)
     - No console errors during scenario (check console.jsonl or use a flag tracked during capture)
   - Build criteriaResults object: `{ canvasContainersPresent: { pass: boolean, value: number }, noConsoleErrors: { pass: boolean, errorCount: number } }`.
   - Determine overall result: `const result = allCriteriaPassed ? 'pass' : 'fail';`

7. **Finalize:**
   - `await ctx.finalize(result, criteriaResults);`
   - Use Playwright `expect()` to assert pass for CI-friendly output:
     ```javascript
     expect(finalSnap.canvasContainerCount, 'Canvas containers must be present after zoom cycle').toBeGreaterThanOrEqual(1);
     ```

**Console error tracking approach:** To track console errors for pass/fail criteria, add a separate `page.on('console')` listener in the test that simply counts error-level messages. This is independent from console-capture.mjs (which writes to JSONL). Keep it simple -- just an `errorCount` variable incremented on `msg.type() === 'error'`.

**Important:** Do NOT use `waitForTimeout()` anywhere. Use `waitFor('ready')` for all settling (established Phase 6 pattern).
