<!-- Skip-guard pattern (Phase 27 invention; reused verbatim Phase 28/29/30/35) -->

From any Phase 27/28/29/30 unit test scaffold, the per-test guard looks like:

```javascript
import { describe, it } from 'node:test';
import { existsSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import path from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);

const TARGET = path.resolve(__dirname, '../../src/path/to/module.js');
const SKIP_REASON = !existsSync(TARGET)
  ? 'production module not yet present (Plan 31-NN)'
  : false;

describe('module under test', () => {
  it('lock contract A', { skip: SKIP_REASON }, async () => {
    const mod = await import(TARGET);
    // assertions
  });
});
```

Critical detail: the dynamic `await import(TARGET)` is INSIDE the `it()` body so the import is never attempted when the file is missing — the skip happens first via `{ skip: SKIP_REASON }`. Synchronous top-level imports of the missing module would crash the whole describe block.

For grep-based contracts (e.g. asserting App.jsx has `crypto.randomUUID()` in counter overlays), use `readFileSync` instead of `import`:

```javascript
import { readFileSync } from 'node:fs';
const SOURCE = readFileSync(TARGET, 'utf8');
const matches = SOURCE.match(/data\.id\s*=\s*crypto\.randomUUID\(\)/g) || [];
assert.ok(matches.length >= 2, `expected >=2 matches, got ${matches.length}`);
```
