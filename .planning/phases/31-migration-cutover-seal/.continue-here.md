## Outstanding concern (out of Phase 31 scope, plan separately)

**No `doc_yjs_state` writes seen in tonight's log.** Y.Doc updates persist
locally via IndexedDB and broadcast via Realtime, but the server-side
snapshot table appears not to be receiving snapshots. This means a fresh
device opening the same doc later may see only what's still in the legacy
table (which is fine because backfill re-runs on first open of an
unmigrated doc). For multi-device cold-start in the post-cutover era, a
Phase 32+ followup needs to wire the SupabaseYjsProvider snapshot persist
or a Hocuspocus equivalent. Don't bundle this into Phase 31 close.
