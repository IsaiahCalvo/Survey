The hook already has two helper functions defined inline (per Plan 30-07 SUMMARY):
- `fanOutCrdtForAnnotationsByPage(annotationsByPage, { documentId, userId })` — per-row CRDT-side write for every non-highlight non-callout fabric obj. Calls `dualWriteFabricCommit` with `skipLegacy: true` (because the bulk path already fired in the legacy flow).

When the legacy path is killed by this plan, these helpers must be called WITHOUT `skipLegacy` (or with `skipLegacy: false`) so the dual-write helper fires both sides — except in this plan's path "both sides" means "CRDT only" because the bulk path didn't run. The cleanest implementation: call `dualWriteFabricCommit` directly per-row without `skipLegacy`, OR add a new flag to the helper signature.

Simpler implementation: keep the existing helpers byte-identical and ALSO keep `skipLegacy: true`. When the legacy path is killed, the CRDT-only writes are correct because the helpers are gated on `isCRDTEnabled() && phase30Ydoc`, and the CRDT path with `skipLegacy: true` writes ONLY to the Y.Doc. That's exactly the post-cutover contract. So the simplest gate is: skip the legacy bulk call AND keep calling the same fan-out helper. The fan-out is no longer "fan-out" semantically (no parallel legacy write) but the code path is byte-identical to Phase 30.
