**Why this matters:** During edit mode, `editingAnnotationIndex != null`, so `isInteractive === false`, so the entire SVG root gets `pointerEvents: 'none'`. The mtr handle rendered in the `isEditing=true` branch will therefore be non-interactive purely via the SVG root gate — the `pointerEvents: 'none'` on the branch's own elements is belt-and-suspenders but not load-bearing for interactivity.

**However**, Plan 13-01's delegated `pointerover`/`pointerout` listener is attached to `svgRef.current` which is the SVG root itself. Event listeners attached via `addEventListener` still fire on elements with `pointerEvents: 'none'` when the OS dispatches pointer events through the SVG, but pointer events do NOT pass through elements with `pointerEvents: 'none'` — they're filtered BEFORE bubbling. Therefore: hovering the edit-mode mtr handle will NOT fire pointerover on svgRef because the entire SVG has pointer-events:none. This is EXPECTED and CORRECT — Plan 13-01's effect-top edit-mode gate already returns early while `editingAnnotationIndex != null`, so even if the listener did fire, no pill would arm. The two mechanisms compound.
