# Phase 14 — UI Design Contract

> Visual and interaction contract for the SVG render unification + shared tool foundation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing:** Phase 14 is a render-pipeline unification phase, not a chrome-building phase. The "UI" surface is SVG render primitives (stroke, fill, dash, foreignObject text styling), cursor state, and keyboard affordances — not a new panel or modal. The contract below locks the visual values the executor will bake into `renderCallout`, the callout creation preview, the dashed line/arrow preview, the crosshair cursor rule, and the Delete/Backspace keyboard response. Existing app chrome (toolbars, modals, auth, account-settings) is NOT in scope and is not re-specified here.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React 18 + Vite + Fabric.js 5.5.2 with hand-rolled CSS) |
| Preset | not applicable |
| Component library | none — native SVG primitives + Fabric.js Textbox for edit mode |
| Icon library | none (no new icons in this phase) |
| Font | `Arial` (single-name family, chosen per CLAUDE.md 2026-04-08 Fabric.js cursor-drift rule; NO CSS fallback stacks) |

**Why no shadcn:** This project is not a shadcn/Tailwind app. It uses plain CSS files (`src/App.css`, `src/index.css`, `src/styles.css`, per-component `.css` files) and native SVG rendering through `svgAnnotationRenderers.jsx`. Introducing a design system mid-milestone into a 28 KLOC `App.jsx` would violate the Always-Protected boundary. Phase 14 adds zero dependencies (confirmed in `14-RESEARCH.md` — "Installation: None").

**Font family rule (load-bearing gotcha):** Per `CLAUDE.md` 2026-04-08 gotcha, Fabric.js Textbox `fontFamily` must be a single font name. This rule extends in Phase 14 to:
1. The Textbox inside the Fabric Group produced by `calloutEditAdapter.toFabricGroup()`.
2. The `<foreignObject>` inner `<div>` font-family in the revised `renderCallout`.
3. The `defaultCalloutStyle.fontFamily` at `src/components/Callout/types.js:122` — currently `'Inter, Arial, sans-serif'` which is a CSS fallback stack and MUST be sanitized to `'Arial'` before being assigned to any Fabric.js object or foreignObject div in the new render path. This is the correction flagged in `14-RESEARCH.md` item 3.

## Spacing Scale

Declared values (all from the standard 8-point set {4, 8, 16, 24, 32, 48, 64}, applied to SVG render primitives in page coordinates):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Text box inner padding (`renderCallout` foreignObject div padding); textbox corner radius `rx/ry` |
| sm | 8px | Reserved for future callout handle gap (Phase 17/18) |
| lg | 16px | Reserved for future mini-toolbar padding (Phase 16) |
| xl | 32px | Minimum drag threshold for callout creation (x/y delta below which a mousedown-drag-mouseup cycle does NOT commit a new callout — matches combined-tools creation behavior) |

Exceptions: none.

**Note on the 12px hit-target radius:** The invisible drag-handle hit-circle radius (`r={12}`) documented in Interaction Contract 4 below is NOT a layout spacing token — it is a pointer-interaction affordance value. It is specified once, in context, in the "Callout part drag handles" interaction contract where the muscle-memory-continuity rationale against the deleted `.callout-handle` in `src/index.css:28-34` lives. It intentionally does not appear in this table.

**Dashed preview stroke pattern:** `strokeDasharray="5,5"` (5px on, 5px off). This is NOT a spacing token — it's an SVG stroke attribute value ported verbatim from combined-tools and locked by CREATE-01. Do not parameterize.

**Stroke widths (SVG `stroke-width` values):**

| Use | Width | Notes |
|-----|-------|-------|
| Callout connector line (default) | 2px | Matches `defaultCalloutStyle.lineThickness = 2` in `types.js:118`; existing renderer already enforces `Math.max(1, ...)` floor at `svgAnnotationRenderers.jsx:521` |
| Callout textbox border | `max(1, lineThickness * 0.7) = ~1.4px` | Existing renderer rule at `:577`, preserved verbatim |
| Callout arrowTip circle radius | `max(2, lineThickness + 0.4)` | Existing renderer rule at `:565`, preserved verbatim |
| Dashed preview (line/arrow + callout creation) | Same as committed annotation's `strokeWidth` | Preview must visually match the coming commit — no width difference |
| Selection chrome (reused from existing SVGAnnotationLayer) | 1px with `vectorEffect: 'non-scaling-stroke'` | Not specified by this phase — existing selection overlay stroke rules inherited |

## Typography

Phase 14 renders three distinct text surfaces. All three use **Arial** as a single-name family (no fallback stack):

| Role | Size | Weight | Line Height | Rendered Where |
|------|------|--------|-------------|----------------|
| Callout body (committed) | 14px | 400 (regular) | 1.2 | `<foreignObject>` inner `<div>` in revised `renderCallout` |
| Callout body (edit mode) | 14px | 400 (regular) | 1.2 | Fabric.js Textbox inside the Group produced by `calloutEditAdapter.toFabricGroup()` |
| Callout body (user-overridden) | `callout.style.fontSize` (10-32px allowed per `fontSizes` in `types.js:176`) | inherits `bold` boolean from style | 1.2 | Both surfaces (committed + edit) — user control via existing style shim |

**Font-smoothing contract** (mandatory in the revised `renderCallout` foreignObject inner div, matching `renderText` at `svgAnnotationRenderers.jsx:413-485`):

```js
WebkitFontSmoothing: 'antialiased',
MozOsxFontSmoothing: 'grayscale',
```

Without these two properties, the SVG-rendered callout text will look visually different from the Fabric.js Textbox text during edit mode — a regression risk the `renderText` template already solved. Copy verbatim.

**Rationale for 14px default:** Preserves the existing `defaultCalloutStyle.fontSize = 14` from the deleted HTML overlay, so legacy callouts saved before Phase 14 round-trip at the same visual size — required by the "Data-model continuity" success criterion (Phase 14 boundary: byte-identical JSON round-trip). 14px also matches the most common callout size in user test data per the existing preset `fontSizes` array.

## Interaction Contracts (Phase-specific — extends the template)

Phase 14 introduces or changes four interactive surfaces. Each has a precise visual/behavioral contract:

### 1. Crosshair cursor (UX-01)

| Trigger | Cursor | Applied Where |
|---------|--------|---------------|
| `activeTool === 'line' \|\| activeTool === 'arrow' \|\| activeTool === 'callout'` AND no drag in progress | `cursor: crosshair` | SVG root in `SVGAnnotationLayer.jsx:~1099-1114` AND `FabricDrawingCanvas.jsx:510` (already hardcoded at `:510` — verified in `14-RESEARCH.md` correction #2) |
| Tool deactivates OR creation drag starts OR hover an existing selected annotation | `cursor: default` or `move` or `grab` (existing SVGAnnotationLayer rules at `:949, :1111, :1201, :1303`) | SVG root |
| Drag in progress (`interactionState === 'dragging'`) | `cursor: grabbing` | Already correct at `:1111` — do not modify |

**CSS implementation:** Per CONTEXT.md Area 4 decision, use a conditional CSS class `tool-crosshair` (exact name is Claude's discretion). Prefer a class over an inline `cursor:` string so the existing selection/hover cursor rules at `:949-1303` keep composing correctly via specificity. The class definition lives in `src/index.css` in the `/* Phase 14 — tool crosshair */` comment block.

**Load-bearing gotcha from RESEARCH:** `SVGAnnotationLayer.jsx:1109` currently sets `pointerEvents: isInteractive ? 'auto' : 'none'` and `isInteractive` is `select`/`text-select` ONLY (line 142). When `activeTool` is line/arrow/callout the SVG layer currently has `pointerEvents: 'none'` — so the crosshair class alone will not show the cursor. Plan must address pointerEvents gating for line/arrow/callout tool modes, not just cursor styling. Executor: do NOT set `pointerEvents: 'auto'` blindly — that would re-enable annotation click-to-select during drawing which breaks the existing select-vs-draw contract. Instead, add line/arrow/callout to `isInteractive` AND ensure click handlers on annotations are gated by `activeTool === 'select'`. Surgical.

**UX comment requirement (per CLAUDE.md feedback_ux_comments rule):** Every line of code that sets cursor, pointer-events, or the new `tool-crosshair` class must carry a code comment explaining why. Example: `// UX: crosshair while line/arrow/callout tool is active (UX-01) — signals "click-drag to create"`. Required on every edit, no exceptions.

### 2. Delete/Backspace keyboard shortcut (KBD-01)

| Condition | Action |
|-----------|--------|
| User has `selectedIds.length > 0` OR `selectedCalloutIds.length > 0` AND `isUserTyping() === false` AND `e.key === 'Delete' \|\| e.key === 'Backspace'` | Delete selected annotation/callout, save undo checkpoint, clear selection state |
| `isUserTyping() === true` (focus in text input, textarea, contentEditable, Fabric.js hidden textarea) | No-op — do not preventDefault, let the keystroke edit text normally |
| No selection | No-op |

**No visual feedback in Phase 14** — the annotation/callout simply disappears. Phase 18 CALL-08 will add empty-text self-destruct which is a separate behavior.

**Focus-guard implementation:** `isUserTyping()` helper ported from combined-tools `Index.tsx:31-49`. Checks:
1. `document.activeElement?.tagName === 'INPUT'`
2. `document.activeElement?.tagName === 'TEXTAREA'`
3. `document.activeElement?.isContentEditable === true`
4. `document.activeElement?.closest('.fabric-hidden-textarea')` (Fabric.js edit-mode textarea)

Inline the helper into the `SVGAnnotationLayer.jsx` keydown effect OR extract as a tiny shared util at `src/utils/keyboardFocus.js` — Claude's discretion per CONTEXT.md.

**CalloutOverlay handler removal (load-bearing per RESEARCH):** The existing `<CalloutOverlay>` at `src/components/Callout/index.jsx:55-80` has its OWN duplicate Delete/Backspace handler. Phase 14 must kill that handler when the Callout/ directory is deleted. Grep for `'Delete'` and `'Backspace'` in `src/components/Callout/*` before the delete commit to confirm no orphaned listener survives.

### 3. Dashed creation preview (CREATE-01)

| Surface | Stroke | Dash pattern | Opacity | Where |
|---------|--------|--------------|---------|-------|
| Line preview (mid-drag) | User's current line color + thickness | `[5, 5]` | `0.6` | Fabric.Line at `FabricDrawingCanvas.jsx:287-292` |
| Arrow preview (mid-drag) | User's current arrow color + thickness | `[5, 5]` | `0.6` | Fabric.Line at `FabricDrawingCanvas.jsx:287-292` (same path as line) |
| Line commit (mouse-up) | User's current line color + thickness | `null` (solid) | `1.0` (or tool default) | Reset BEFORE `commitShape` call at `:243-263` per RESEARCH correction #3 |
| Arrow commit (mouse-up) | Same | `null` | `1.0` | Same reset |
| Callout preview (mid-drag) | `defaultCalloutStyle.borderColor = #1e293b`, lineThickness 2px | `"5,5"` (string form for SVG attribute) | `0.6` | New transient React state in `SVGAnnotationLayer`, renders `<g className="callout-preview">` |
| Callout commit (mouse-up) | `defaultCalloutStyle` solid | (solid, no dash) | `1.0` | New callout added via `onCreateCallout` callback → `setCallouts` |

**Load-bearing gotcha from RESEARCH correction #3:** `commitShape` at `FabricDrawingCanvas.jsx:243-263` calls `shape.toJSON(CUSTOM_PROPS)` BEFORE `canvas.remove(shape)`. If the dashed-preview style is still on `shape` at the moment `toJSON` runs, the dashed attributes get serialized and persisted into Supabase. The reset MUST happen between the `hasSize` check (whatever gates the commit) and the `commitShape` call. Executor: confirm the reset lands before `toJSON`, not after, and include a Playwright test that saves a line, reloads, and asserts `strokeDashArray === null` on the reloaded annotation.

**Callout preview composition (locked):**

The transient `<g className="callout-preview">` SVG group contains exactly these children, in this order:

1. `<rect>` — previewed textbox at the current mouse position. Hardcoded default size `120px × 40px` (scaled to the correct page coordinate units via `effectiveScale`). `fill="#ffffff"`, `stroke="#1e293b"`, `stroke-width="2"`, `stroke-dasharray="5,5"`, `opacity="0.6"`, `rx="4"`, `ry="4"` (matches existing `renderCallout` rx/ry at `:578`).
2. `<line>` — line1 from textbox edge to `knee`. `stroke="#1e293b"`, `stroke-width="2"`, `stroke-dasharray="5,5"`, `opacity="0.6"`, `stroke-linecap="round"`.
3. `<line>` — line2 from `knee` to `arrowTip`. Same stroke rules.
4. `<polygon>` — preview arrowhead at `arrowTip`. 6-point solid triangle, `fill="#1e293b"`, `opacity="0.6"`.

`knee` computed per combined-tools creation formula from CONTEXT.md Area 4: `knee = { x: (arrowTip.x + currentPointer.x)/2, y: arrowTip.y - 40 }`. The `-40` is a pixel value in page coordinates — convert to normalized on commit.

On mouseup, the preview group is unmounted (React state clear) AND the committed callout becomes the new element in `callouts[]` via `setCallouts`. On tool switch mid-drag (user hits `V` for select while holding mouse), the preview state clears per the CONTEXT.md "How transient callout-preview state is cleared on tool switch" discretion item — choose the same pattern the existing line/arrow preview uses (likely: listen to `activeTool` prop in effect cleanup).

### 4. Callout part drag handles (basic MVP — no chrome yet)

Phase 14 does NOT render visible circle/square handles on selected callouts. Selection chrome lands in Phase 17/18. What Phase 14 ships:

| Part | Hit target | Cursor on hover | Cursor on drag |
|------|------------|-----------------|----------------|
| arrowTip | Existing `<circle>` already rendered at `svgAnnotationRenderers.jsx:562-567` (radius `max(2, lineThickness + 0.4)` ≈ 2.4px — too small for touch; enlarge hit target to 12px via a transparent `<circle>` overlay or `pointer-events` on a parent `<g>`) | `grab` | `grabbing` |
| knee | No visible element today. Add a transparent `<circle cx={knee.x} cy={knee.y} r={12} fill="transparent" pointer-events="all" data-callout-part="knee" />` as an invisible hit target. Radius 12px matches the deleted HTML overlay's `.callout-handle` 12×12 size in `src/index.css:28` — preserved for muscle-memory continuity. | `grab` | `grabbing` |
| textBox body | Existing `<rect>` at `:569-581` gets `data-callout-part="textBox"`. Hit the full rect. | `grab` | `grabbing` |
| Connector line1 / line2 (whole-move trigger) | Existing `<line>` elements at `:544-560` get `data-callout-part="line1"` and `"line2"`. Stroke-width is ~2px which is too thin for touch — overlay a transparent `<line>` with `stroke-width="12"` to widen the hit target. | `move` | `grabbing` |
| Any part + Cmd/Ctrl modifier | (whole-move trigger fallback) | `move` | `grabbing` |

**Rationale for invisible hit-targets:** Phase 14 needs the drag behavior to work without building visible selection chrome (chrome is Phase 17/18). The pattern of "visible `<element>` + transparent hit overlay at 12px radius" mirrors how the existing rotation handle `data-rotation-handle="mtr"` delegation works in `SVGAnnotationLayer.jsx:213-313` (Phase 13 EDIT-13). Data attributes enable event delegation — Phase 17/18 will replace the invisible overlays with visible chrome that reuses the same `data-callout-part` hit-test pathway.

**Why 12px (hit-target radius, not layout spacing):** The 12px radius is a pointer-interaction affordance value, not a spacing token. It is the hit-target radius of the invisible `<circle>` drag overlay on the knee handle (and the enlarged `<circle>` overlay on the arrowTip, and the `stroke-width="12"` transparent line overlay on line1/line2). Its sole source of truth is the deleted HTML overlay's `.callout-handle` size in `src/index.css:28-34` (`width: 12px; height: 12px; border-radius: 3px`). Preserving the exact 12px value is deliberate muscle-memory continuity for users who interacted with the legacy callout before Phase 14 — they will find hit targets in the same physical size they have learned. Phase 17/18 may revisit the value when visible chrome lands.

**No selection highlight in Phase 14:** Clicking a callout sets `selectedCalloutIds = [id]` in React state but there is NO visible selection indicator (no glow, no border color change, no handles drawn). Verification of "is this callout selected?" in Phase 14 happens via React DevTools or a console log. The visual selection chrome is Phase 17/18's job. This is acceptable because Phase 14's target audience for intermediate state is Claude building Phases 15-18, not end users, per CONTEXT.md "Specific Ideas" item 3.

## Data Attributes Contract (locked for Phase 17/18 handoff)

Phase 14 adds these data attributes to every element rendered by `renderCallout`. These are the hit-test contract for Phases 17/18 event delegation:

| Element | Attribute | Value |
|---------|-----------|-------|
| Outer `<g>` wrapper | `data-callout-id` | `{callout.id}` |
| `<circle>` arrowTip | `data-callout-part` | `"arrowTip"` |
| Invisible `<circle>` knee overlay | `data-callout-part` | `"knee"` |
| `<rect>` textbox | `data-callout-part` | `"textBox"` |
| `<foreignObject>` text content | `data-callout-part` | `"text"` |
| `<line>` line1 | `data-callout-part` | `"line1"` |
| `<line>` line2 | `data-callout-part` | `"line2"` |

**Invariant:** Every pointer event inside a callout's `<g>` subtree can be resolved to a `(calloutId, partType)` pair by walking the event target's ancestors with `e.target.closest('[data-callout-id]')` and reading `dataset.calloutPart` from the nearest matching child. This is the Phase 13 EDIT-13 pattern applied verbatim.

**DO NOT collide with the rotation handle delegation:** Rotation handles use `data-rotation-handle="mtr"`. The callout attribute namespace is `data-callout-*` — they do not overlap. Keep them disjoint.
