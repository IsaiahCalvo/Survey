<decisions_made>

This fixes the position/scale flicker that occurred when PAL repainted one page at a new scale while others were still at the old scale.

- First attempt (reverted) applied wrong ratio in ref callback (`currentAppScale / baseScale` instead of `currentAppScale / pageBase`) — caused annotations to flicker out of position. Second attempt uses per-page base scales consistently across all code paths.

<context>
The annotation disappearance during zoom has THREE distinct causes, each requiring a different fix:

1. **Wrong CSS transform ratio after PAL repaints** — FIXED with per-page base scales. When PAL repaints a page at a new zoom level, the old global base scale produces wrong ratios for that page. Per-page tracking solves this.

2. **Naked DOM nodes when React recreates overlay divs** — FIXED with ref callback zoom transform. When Syncfusion triggers a React re-render that creates a new overlay content div, the new node had no CSS transform until the next zoom event. Now the ref callback applies the correct transform immediately.

3. **Portal hosts destroyed by Syncfusion page re-renders** — FIX APPLIED BUT UNTESTED. Syncfusion replaces page DOM containers during zoom. Without portal host freezing, `pageHost.isConnected` becomes false → overlay returns null → annotations vanish. Fixed by activating `shouldFreezePortalHost` during zoom overlay transforms and keeping the portal cache warm.

The profiler confirmed 0% untransformed during zoom with fixes 1 and 2, but user still saw disappearance — that's cause 3 (portal hosts).

Key architecture: Two separate CSS transform systems operate during zoom:
- **Overlay content div** (syncfusionOverlayContentRefs) — managed by handleSyncfusionZoomChange in App.jsx
- **Fabric wrapper** (canvas.wrapperEl) — managed by PAL's settle callback
These are nested (overlay wraps PAL wrapper wraps canvas). Both must be consistent for correct visual scaling.
</context>
