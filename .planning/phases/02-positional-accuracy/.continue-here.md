**This session — REVERTED 15-17 and applied targeted fixes:**

User tested commits 15-17 and reported worse behavior (annotations disappearing during zoom). Reverted working tree to Phase 1 baseline (commit 2ea6802, only diff was settle timer 1000→4000ms).

Diagnosed the real issue: Phase 1 relied on interaction tracking's 300ms settle to defer scale commits during zoom. When Syncfusion's blocking re-renders (600ms+) caused gaps in interaction events, interaction went idle → setScale() fired → PAL rebuilt canvas mid-zoom → annotations vanished.

Applied 7 targeted edits to App.jsx:

1. **shouldDeferScaleCommit**: Added `zoomOverlayTransformActiveRef.current` — defers setScale() during zoom regardless of interaction state
2. **shouldFreezePortalHost**: Added `|| zoomOverlayTransformActiveRef.current || syncfusionScaleConfirmPendingRef.current` — keeps portal hosts frozen during zoom AND during post-zoom PAL rebuild
3. **layerScale freeze**: Uses `zoomOverlayBaseScaleRef.current` during active zoom — prevents PAL from getting new scale prop mid-zoom
4. **Settle timer (1000ms)**: Instead of immediately removing CSS transforms, flushes deferred scale and sets confirm-pending. CSS transforms stay until PAL rebuilds each page.
5. **handlePALScaleApplied**: Bridges CSS transforms during active zoom (computes ratio from applied scale to current app scale). During confirm-pending, removes transforms per-page as each canvas completes.
6. **Portal host caching**: Always caches connected hosts (warm cache for when freeze activates)
7. **Overlay content ref callback**: Applies CSS transform to new nodes created during zoom (e.g., when Syncfusion replaces page containers)
8. **Safety timers**: Clean up zoom overlay state when PAL never confirms (800ms safety)

<decisions_made>

- **Reverted stopPropagation + deferred zoomTo + page container transforms**: User reported these made zoom behavior worse (annotations disappearing during zoom). Went back to Phase 1 baseline where Syncfusion processes each wheel event normally via zoomTo().
- **Three-ref freeze during zoom**: `zoomOverlayTransformActiveRef.current` gates shouldDeferScaleCommit, shouldFreezePortalHost, and layerScale freeze. This is more reliable than depending on interaction tracking's 300ms settle.
- **Two-phase settle pattern**: Settle timer (1000ms) releases zoom overlay but sets confirm-pending. PAL rebuilds at final scale, handlePALScaleApplied removes CSS transforms per-page. 800ms safety timer forces cleanup if PAL never confirms.
- **Always-cache portal hosts**: Moved portal host caching outside the freezeDuringInteraction block so the cache is warm when freeze activates.
- **Bridge CSS transforms in handlePALScaleApplied**: During active zoom, if PAL rebuilds a page (e.g., visibility change), the CSS transform is updated to bridge from the new canvas scale to current app scale, preventing visual mismatch.

Key architecture:
- Wheel handler: App.jsx onWheel, calls viewer.magnificationModule.zoomTo(nextZoom) directly (no deferral)
- handleSyncfusionZoomChange: fires on each zoom step, applies CSS scale() to overlay content divs, defers setScale(), starts 1000ms settle timer
- Settle timer: releases zoomOverlayTransformActiveRef, flushes deferred scale via setScale(), sets syncfusionScaleConfirmPendingRef = true
- handlePALScaleApplied: removes CSS transform per-page as canvas rebuilds. When all confirmed, cleans up.
- Safety timer: 800ms after settle, forces cleanup if PAL never confirms
- layerScale: frozen to zoomOverlayBaseScaleRef.current during active zoom → PAL keeps rendering at pre-zoom scale
- shouldFreezePortalHost: includes zoom refs → portal hosts stay frozen during entire zoom + rebuild cycle

The fix prevents annotations from disappearing at any point:
1. During zoom: CSS transforms scale annotations. PAL's scale frozen → no rebuild → no flash
2. After settle: deferred scale flushes → PAL rebuilds → handlePALScaleApplied removes CSS transform per-page → seamless transition
