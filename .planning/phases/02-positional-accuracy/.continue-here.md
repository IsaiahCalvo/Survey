11. **Analyzed 1.log profiler data (45K lines)** — Confirmed CSS transforms ARE being applied during ctrl-wheel zoom (`observedScale: 5.84`, `hasTransform: true`, `missingOverlayCount: 0`). Profiler says overlays are present and transformed. But user sees disappearance.

12. **Identified the real root cause chain:**
    - `isZooming` comes from `useZoomState(scale)` (src/hooks/useZoomState.js:31)
    - `isZooming = Math.abs(cssScale - 1) > 0.001` where `cssScale = targetScale / renderedScale`
    - Since `setScale` is DEFERRED during zoom, `targetScale` never changes → `isZooming = false` always
    - PAL receives `isZooming={false}` as prop → `isZoomingRef.current = false`
    - When PAL detects a scale change (frozen layerScale differs from canvas's current zoom), it enters zoom mode with 300ms settle timer
    - Settle timer callback checks `isZoomingRef.current` — it's `false` → proceeds immediately
    - Calls `fc.renderAll()` — 200-800ms synchronous main thread block — canvas goes BLANK mid-zoom
    - CSS transform scales a blank canvas wrapper → user sees nothing

13. **Identified toolbar zoom identity transform bug:**
    - For toolbar zoom, `payload.zoomValue` reports the SAME value as current zoom
    - `scaleRef.current` doesn't change → CSS transform ratio = 1 (identity)
    - Profiler confirms: toolbar zoom has `untransformedPct: 52.94%`, ctrl-wheel has 0%
    - `appScale` stays at 1.20998 throughout toolbar zoom gesture

<decisions_made>

- **Root cause was NOT setScale triggering re-renders** (previous session's hypothesis was partially wrong). The deferred setScale IS working — React state doesn't change during zoom. But the layerScale FREEZE gives PAL a different scale than what its canvas is at, and PAL's own settle timer fires immediately because isZooming is false.
- **CSS transform approach IS fundamentally correct** — profiler confirms transforms are applied and overlays are present during ctrl-wheel zoom. The issue is that the canvas CONTENT inside the transformed wrapper goes blank during Fabric.js rebuilds.
- **The profiler has a blind spot** — it checks overlay presence, CSS transforms, and visibility, but NOT whether the Fabric.js canvas has actual content. This is why profiler shows "everything fine" but user sees disappearance.
- **Two separate bugs**: (1) PAL rebuilds mid-zoom due to false `isZooming`, (2) toolbar zoom produces identity transforms.
</decisions_made>
