# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Overlay Attachment Foundation.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Classification: Infrastructure (Non-Visual)

Phase 1 creates invisible, inert DOM elements (overlay divs) that serve as portal
targets for later phases. There are **no user-facing visual changes** in this phase.
The overlay divs are empty, transparent, and have `pointer-events: none`. Users will
see zero difference in the application before and after this phase is complete.

The visual contract for this phase is therefore a **non-interference contract**: the
new DOM elements must be invisible and must not alter the appearance or behavior of
any existing UI element.

## Overlay Div Visual Contract

This section replaces the standard visual contract sections for this infrastructure phase.
It defines the exact CSS properties and DOM structure that constitute the "visual contract"
for overlay divs.

### Required CSS Properties

Every overlay div created by `attachOverlayToPageDiv()` MUST have exactly these styles:

| Property | Value | Rationale |
|----------|-------|-----------|
| `position` | `absolute` | Positions overlay relative to the Syncfusion page div (which has `position: relative`) |
| `top` | `0` | Aligns to top edge of page div |
| `left` | `0` | Aligns to left edge of page div |
| `width` | `100%` | Fills the full width of the page div |
| `height` | `100%` | Fills the full height of the page div |
| `pointer-events` | `none` | Overlay must not intercept any mouse/touch events; the existing annotation system handles interaction |
| `z-index` | `20` | Matches existing `liveRoot` z-index (design spec Step 1). Stacking order with existing liveRoot is irrelevant because overlay div is empty and transparent |

**Inline style string (canonical form):**
```
position:absolute;top:0;left:0;width:100%;height:100%;pointer-events:none;z-index:20;
```

**Source:** Design spec Step 1 (`docs/superpowers/specs/2026-03-17-option3-direct-child-canvas-design.md`) and existing `liveRoot` styling at App.jsx line 9638.

### Required Data Attribute

| Attribute | Value | Purpose |
|-----------|-------|---------|
| `data-overlay-page` | Page number as string (e.g., `"6"`) | Debugging identification and Playwright test selectors |

**Source:** Follows existing pattern of `data-stable-portal`, `data-stable-live-root`, `data-stable-snapshot-root` (01-RESEARCH.md Pattern 5).

### DOM Structure Contract

```
e-pv-page-div[data-page-number="N"]          (Syncfusion page div, already exists)
  +-- [existing Syncfusion children]          (text layer, canvas, etc.)
  +-- [existing stable portal host]           (current system, untouched)
  +-- div[data-overlay-page="N"]              (NEW: overlay div from this phase)
```

The overlay div MUST be a **direct child** of the Syncfusion `e-pv-page-div` element. Not a grandchild, not nested inside another wrapper.

### Non-Interference Verification Criteria

The overlay divs must satisfy ALL of these visual non-interference checks:

| Check | Method | Expected Result |
|-------|--------|-----------------|
| Invisible to user | Visual inspection at any zoom level | No new borders, backgrounds, shadows, or text visible |
| No layout shift | Compare page div dimensions before/after overlay attachment | Page div `offsetWidth` and `offsetHeight` unchanged |
| No pointer blocking | Click/draw on existing annotations | All existing annotation interactions (select, draw, move, resize) work identically |
| No scroll interference | Scroll through document pages | Scroll behavior unchanged, no jank or missed scroll events |
| No z-index conflict | Inspect stacking in DevTools | Overlay div does not obscure any existing interactive element (it is empty and transparent) |
| Existing annotations render | Navigate to page 6 of test PDF | All existing annotations visible and correctly positioned |

## States and Transitions

Phase 1 has no user-visible states. The overlay div lifecycle is purely internal:

| Internal State | When | Visible Effect |
|----------------|------|----------------|
| Overlay div not yet created | Before `syncfusionPageContainers` detects the page div | None -- page renders normally |
| Overlay div created and attached | After `attachOverlayToPageDiv()` runs for a page | None -- overlay is invisible |
| Overlay div detached (Syncfusion recreation) | Syncfusion destroys page div during zoom | None -- basic re-attachment in useEffect; full robustness deferred to Phase 5 |
