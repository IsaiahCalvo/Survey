## Typography

Phase 11 introduces two text-rendering contexts: (1) the Fabric.js IText editing surface (user-authored annotation text), and (2) the floating mini-toolbar for shape property editing. Each has distinct typography rules.

### Annotation Text (IText on Canvas)

The font used inside IText comes from the annotation's own Fabric.js JSON data (stored `fontFamily`, `fontSize`, `fontWeight`). The UI-SPEC does NOT prescribe these -- they are user data. FabricEditCanvas must preserve whatever the annotation JSON specifies.

### Mini-Toolbar UI Chrome

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Label | 12px | 500 | 1.3 | var(--font-primary) |
| Value readout | 12px | 400 | 1.3 | var(--font-primary) |

**Source:** Matches existing toolbar label sizes in App.css (12px labels at line 226-227). Mini-toolbar uses the smaller end of the scale because it is a floating overlay that must not dominate the editing area. Two weights provide visual contrast between interactive values (regular 400) and their descriptive labels (medium 500).

### Cursor Feedback During Text Editing

| State | Cursor |
|-------|--------|
| Hovering text annotation (select tool) | `pointer` |
| Text annotation selected | `move` |
| Double-click triggered, IText editing active | `text` (Fabric.js default for IText) |
| Click-to-place new text (text tool active) | `text` |

## Color

This phase does NOT introduce new application-level colors. All colors come from the existing `:root` CSS variables in `App.css`. The contract below maps existing tokens to Phase 11 usage.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | transparent | Canvas background is transparent; PDF page shows through |
| Secondary (30%) | `--bg-tertiary` (#2D2D2D) | Mini-toolbar background, tooltip background |
| Accent (10%) | `--accent-primary` (#4A90E2) | Active edit border glow around bbox Canvas, active tab highlight in mini-toolbar |
| Destructive | `--accent-red` (#DC3545) | Not used this phase (no delete actions in edit Canvas) |
| Border | `--border-primary` (#3A3A3A) | Mini-toolbar border, separator lines between toolbar groups |

| Text muted | `--text-muted` (#9A9A9A) | Mini-toolbar placeholder text, disabled states |
| Shadow | `--shadow-md` | Mini-toolbar drop shadow |

### Canvas Edit Border

When a bbox Canvas is mounted for text/shape editing, a 1px solid border using `--accent-primary` (#4A90E2) at 40% opacity appears around the Canvas container. This provides a subtle visual indicator that the user has entered edit mode without overwhelming the editing surface.

```
border: 1px solid rgba(74, 144, 226, 0.4)
border-radius: 2px
```

Accent reserved for: edit-mode Canvas border glow, active mini-toolbar tab indicator, and text cursor blink color (Fabric.js default).

## Interaction States

### Text Annotation Edit Flow

| Step | Visual State | Trigger |
|------|-------------|---------|
| 1. Hover | SVG annotation shows pointer cursor | Mouse enters annotation hit area |
| 2. Select | Blue selection overlay with 8 handles appears | Single click |
| 3. Enter edit | Selection overlay hides. Bbox Canvas mounts over annotation. IText cursor appears. Canvas has subtle blue border. | Double-click |
| 4. Editing | Standard text editing: type, select, cursor blink. Canvas auto-expands if text grows beyond bbox. | Keyboard input |
| 5. Commit | Canvas unmounts. SVG updates with new text. Selection overlay reappears with updated bounds. | Click outside Canvas OR press Enter (for single-line) |
| 6. Cancel | Canvas unmounts. SVG reverts to pre-edit state. No selection. | Press Escape |

### New Text Creation Flow

| Step | Visual State | Trigger |
|------|-------------|---------|
| 1. Tool active | Cursor shows `text` over PDF area | Text tool selected in toolbar |
| 2. Click to place | Bbox Canvas mounts at click position. Empty IText in edit mode. Blinking cursor visible. | Click on empty PDF area |
| 3. Editing | Standard text editing: type, select, cursor blink | Keyboard input |
| 4. Commit | Canvas unmounts. New text annotation appears in SVG. | Click outside Canvas |
| 5. Cancel (empty) | Canvas unmounts. No annotation created (empty text discarded). | Click outside with no text entered, OR press Escape |

### Shape Annotation Edit Flow

| Step | Visual State | Trigger |
|------|-------------|---------|
| 1-2 | Same as text (hover, select) | Same as text |
| 3. Enter edit | Selection overlay hides. Bbox Canvas mounts with shape loaded in Fabric.js interactive mode. Fabric.js selection handles visible (blue corner squares). Mini-toolbar floats above or below Canvas. | Double-click |
| 4. Editing | User can drag Fabric.js handles to resize. Mini-toolbar shows color/stroke controls. | Mouse interaction with handles or toolbar |
| 5. Commit | Canvas unmounts. SVG updates with new shape properties. | Click outside Canvas |
| 6. Cancel | Canvas unmounts. SVG reverts to pre-edit state. | Press Escape |

### Callout Annotation Edit Flow

| Step | Visual State | Trigger |
|------|-------------|---------|
| 1-2 | Same as text (hover, select) | Same as text |
| 3. Enter edit | SVG layer hides (same pattern as eraser). Full-page Canvas mounts with callout loaded. All callout parts interactive (text box, knee control point, arrowhead endpoint). | Double-click |
| 4. Editing | User can drag text box, drag knee, drag arrowhead. Full Fabric.js interactive mode. | Mouse interaction |
| 5. Commit | Canvas unmounts. SVG layer unhides with updated callout. | Click outside callout parts |
| 6. Cancel | Canvas unmounts. SVG layer unhides with original callout. | Press Escape |

### Zoom During Edit

| Event | Visual Response | Timing |
|-------|----------------|--------|
| Zoom starts | Current edit state auto-commits. Canvas container gets CSS `transform: scale(newScale/oldScale)` for visual stability (blurry but positioned). | Immediate |
| Zoom settles | Canvas remounts at new dimensions. For text: IText re-enters edit mode with cursor position restored. For shape/callout: re-loaded in interactive mode. | 200ms after last zoom event |

## Layer Stack (z-index)

Phase 11 introduces FabricEditCanvas at a z-index that sits above the SVG layer and selection overlay but at the same level as other Canvas components.

| Layer | z-index | Component |
|-------|---------|-----------|
| PDF page (Syncfusion) | auto | e-pv-page-div |
| SVG annotation display | auto (in portal) | SVGAnnotationLayer |
| SVG selection overlay | auto (after SVG layer) | SVGSelectionOverlay |
| Canvas editing surface | 101 | FabricEditCanvas (same as FabricDrawingCanvas, FabricEraserCanvas) |
| Mini-toolbar (shape edit) | 102 | Floating toolbar positioned above Canvas |
| App modals / dialogs | 1000+ | ConfirmDialog, CalloutEditModal |

**Source:** FabricDrawingCanvas and FabricEraserCanvas both use `zIndex: 101`. FabricEditCanvas follows the same convention. Mini-toolbar at 102 ensures it floats above the Canvas surface.

## Mini-Toolbar (Shape Edit)

A floating toolbar appears when editing shapes (rect, circle, ellipse). It provides property controls without leaving edit mode.

### Layout

```
+--------------------------------------------------+
| Fill: [swatch] | Stroke: [swatch] | Width: [+-]  |
+--------------------------------------------------+
```

- **Position:** Anchored 8px above the bbox Canvas top edge. If insufficient space above, repositioned 8px below the bbox Canvas bottom edge.
- **Width:** Auto-sized to content, minimum 240px, maximum 360px.
- **Height:** Single row, 36px total height (8px padding top/bottom + 20px content).
- **Background:** `--bg-tertiary` (#2D2D2D) with `--shadow-md` drop shadow.
- **Border:** 1px solid `--border-primary` (#3A3A3A).
- **Border radius:** 6px.

### Controls

| Control | Type | Behavior |
|---------|------|----------|
| Fill color swatch | 16x16px color square, 2px border-radius | Click opens CompactColorPicker (existing component) below/above toolbar |
| Stroke color swatch | 16x16px color square, 2px border-radius | Click opens CompactColorPicker |
| Stroke width | +/- stepper buttons with numeric readout (e.g., "3px") | Click +/- adjusts by 1. Range: 1-20. |

### Separator

Vertical 1px line, `--border-primary` (#3A3A3A), height 20px, between each control group.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable -- edit mode is entered via double-click gesture, not a button |
| Empty state heading | Not applicable -- there are no empty states in annotation editing |
| Empty state body | Not applicable |
| New text placeholder | (blinking cursor, no placeholder text -- matches Fabric.js IText default) |
| Error state | "Edit failed -- annotation may have been modified by another user. Changes reverted." |
| Cancel confirmation | None -- Escape cancels immediately with no confirmation dialog (CONTEXT.md: "Escape key cancels edit, revert to pre-edit state") |
| Commit feedback | No toast or notification -- the SVG updating to show the new content IS the feedback |

**Rationale:** This phase is about direct manipulation editing. The primary feedback mechanism is the visual result of the edit appearing in SVG. No modal dialogs, toasts, or notifications are needed for the editing workflow itself.

## Canvas Container Sizing Contract

### Bbox Mode (Text + Shape)

```
position: absolute
left:   (annotation.left - bboxPadding) * effectiveScale
top:    (annotation.top - bboxPadding) * effectiveScale
width:  (annotation.width * annotation.scaleX + bboxPadding * 2) * effectiveScale
height: (annotation.height * annotation.scaleY + bboxPadding * 2) * effectiveScale
zIndex: 101
pointerEvents: 'auto'
border: 1px solid rgba(74, 144, 226, 0.4)
borderRadius: 2px
```

Where:
- `bboxPadding` = 20 (page-coordinate pixels, per CONTEXT.md)
- `effectiveScale` = `containerEl.offsetWidth / pageWidth` (container-aware, per CLAUDE.md)

### Full-Page Mode (Callout)

```
position: absolute
left:   0
top:    0
width:  containerEl.offsetWidth
height: containerEl.offsetHeight
zIndex: 101
pointerEvents: 'auto'
```

SVG layer set to `svgInteractive: false` (hidden) during callout editing, same as eraser pattern.

### Auto-Expand (Text Growing Beyond Bounds)

When IText content grows beyond the initial bbox during editing:
- Canvas width/height increases to accommodate text dimensions + bboxPadding.
- Expansion direction: right and down from the current position (left/top stay fixed).
- Minimum expansion step: none (Fabric.js IText handles this naturally via `object:modified` events).
- Maximum Canvas size: full page dimensions (prevents overflow).

| Context | Tool Active | Cursor |
|---------|------------|--------|
