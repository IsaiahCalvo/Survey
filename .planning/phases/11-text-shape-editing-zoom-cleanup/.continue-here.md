<remaining_work>
### Bug 1: Text wrapping mismatch (ACTIVE)
CSS textarea wraps text at different points than Fabric canvas (canvas measureText is narrower). When entering edit mode, text "unwraps" to fewer lines, shrinking the text box.

**Best fix (option B from analysis):** Before entering edit mode, measure the textarea's actual clientWidth and store in a ref. Use that measurement for Fabric Textbox width. Implementation:
1. In handleTextBoxClick and handleTextBoxDoubleClick, BEFORE calling setIsEditing(true), capture: `textareaWidthRef.current = textareaRef.current?.clientWidth || 0`
2. In the Fabric lifecycle effect, use `textareaWidthRef.current` for tbWidth instead of calculating from innerW - padding
3. This gives the exact pixel width the CSS engine used for wrapping

Current hack: -4px offset on tbWidth — needs testing, likely still imprecise.

### Bug 2: Callout zoom scaling (PRE-EXISTING)
Callouts don't scale with page zoom. They stay fixed size while the PDF page resizes. This is NOT caused by the Fabric text edit changes.

Root cause: CalloutOverlay renders with pixel positions (percentage × pageWidth/pageHeight) but sits outside the SVG viewBox that handles zoom scaling. SVG annotations scale via viewBox automatically; callouts bypass this.

Investigation needed: Check how CalloutOverlay mounts in App.jsx/PageAnnotationLayer.jsx relative to SVGAnnotationLayer. Either move callouts inside the SVG viewBox or apply matching CSS transform.
