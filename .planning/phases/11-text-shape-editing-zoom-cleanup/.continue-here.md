### REAL ROOT CAUSE discovered (unfixed):

User reports three visual bugs that are all the SAME underlying issue:

| Symptom                                          | Canvas (bigger/bolder) | SVG (smaller/crisper) |
|--------------------------------------------------|------------------------|-----------------------|
| 1. Shape edit border/stroke looks different      | Fabric raster stroke   | vector-effect:non-scaling-stroke |
| 2. Rect drawing preview larger than committed    | Live Fabric Canvas     | SVGAnnotationLayer commit |
| 3. Text in edit mode appears bigger than display | Fabric Textbox raster  | foreignObject HTML text |

**Canvas-rendered content is visually bolder/thicker than SVG-rendered content at identical
geometry.** Confirmed by the [SEL-DIFF] log: the numeric bbox coords match to <0.1px, but
the eye still catches a difference.

### Likely causes (to be validated next session):

1. **Canvas 2D anti-aliasing** smears strokes across subpixels; a 2px stroke visually spreads
   to ~2.5px. SVG with `vector-effect: non-scaling-stroke` produces crisp edges.
2. **DPR / Electron zoom factor interaction**: Fabric's internal canvas backing store uses
   `devicePixelRatio`, but in Electron there's an additional zoom factor (see CLAUDE.md
   "Container-aware measurement" gotcha). Mismatch can produce subtly different effective
   stroke widths.
3. **Subpixel positioning**: drawn-shape-container-coords were `(23.43, 23.43, …)` — non-integer
   positions anti-alias the entire edge in Canvas but not in SVG.
4. **For text**: Fabric Textbox raster text uses the browser's default canvas text metrics,
   while HTML text in foreignObject uses subpixel/ClearType rendering. User previously
   accepted this as "Option D" — but now reports text is BIGGER in edit mode, not just
   "different". May need to re-examine.
