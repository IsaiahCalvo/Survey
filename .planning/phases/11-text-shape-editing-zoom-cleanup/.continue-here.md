### Prior session fixes (all uncommitted on Layer-Revamp):
1. **Rotated text/shape edit — CSS rotation on container div**
   - `src/components/FabricEditCanvas.jsx`: Container div gets `transform: rotate(angle)` with `transformOrigin` at annotation center when editing rotated annotations
   - Object inside canvas has `angle: 0` (stripped for easy editing)
   - On commit, original angle restored from `bboxOriginRef.current.angle`

2. **Text flash to top-left on double-click — FIXED**
   - Root cause: `new fabric.Textbox(text, { ...rest })` included original page-space `left`/`top`. Fix: destructure out and set `left: BBOX_PADDING, top: BBOX_PADDING, angle: 0` directly.

3. **Container visibility timing — prevents first-frame flash**
   - Initial `containerStyle` state starts with `{ visibility: 'hidden' }`

### This session fixes (also uncommitted):

4. **useLayoutEffect for container style (attempt 1)**
   - Changed container style computation from `useEffect` to `useLayoutEffect` so positioning happens before browser paint
   - Alone, this didn't fix the jump

5. **Deferred visibility reveal (attempt 2) — UNTESTED by user**
   - Root cause identified: `annotationData.height` was 65.683 but actual text height is 18.08 (3.6x mismatch). Container initially sized for stored height, then canvas loading code shrank it. For rotated elements, this resize shifted the rotation center by ~22px.
   - Fix: Container stays `visibility: hidden` in `useLayoutEffect`. Each canvas loading path (text edit, new text, shape) sets `visibility: 'visible'` AFTER determining actual dimensions.
   - For rotated text edits: `transformOrigin` is recalculated using actual measured text height (not stale stored height) before revealing.
   - Callout mode: visible immediately in useLayoutEffect (no rotation mismatch).
   - **Status: Code written, build passes, but user hasn't tested yet.**
