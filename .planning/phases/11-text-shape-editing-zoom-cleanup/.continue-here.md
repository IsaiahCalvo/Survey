### Bug 6: Text box has no internal padding — PENDING (do this next)
Text renders flush against the text box border with zero padding/margin. All text boxes should have consistent internal padding so text never touches the border edge, regardless of text alignment (left, center, right) or vertical position.
**Where to fix:** Both SVG display (`renderText` in `src/utils/svgAnnotationRenderers.jsx`) and edit canvas (`FabricEditCanvas.jsx` text loading). The inner div/textbox needs padding on all sides.
**Screenshot:** User screenshot from 2026-04-07 shows "tgtgtgtgtg", "Rrvrv", "bnnvnvnnvnvn" all touching the border.

### Bug 5: Text font size/weight mismatch — PENDING
Text appears larger/bolder in FabricEditCanvas edit mode vs SVG display. Container bbox is also larger in edit mode.
**Root cause:** effectiveScale multiplication on fontSize in Fabric.js canvas (`fontSize: Math.round(16 * es)`) vs CSS font rendering in SVG foreignObject (`fontSize: 16px` with SVG viewBox scaling). The rounding and different rendering engines produce different visual sizes.
**Fix approach:** Align FabricEditCanvas text rendering with SVG — likely adjust canvas zoom approach so Fabric.js renders at native font size rather than pre-multiplying by effectiveScale.

### Bug 2: Cursor flicker on click-to-place — DEFERRED
Source is external to FabricEditCanvas (confirmed via diagnostic logging). Likely candidates:

- CSS transition/animation on parent element
- App.jsx render cycle when `editingAnnotation` state changes
**Diagnostic `[EditCanvas]` logging still in FabricEditCanvas.jsx** — 10 log points throughout mount sequence. Remove when done debugging.
**Investigation notes:** See HANDOFF.md for detailed investigation log of all 5 approaches tried.
**Approach for next attempt:** Consider parallel-debug skill to test multiple hypotheses (hiddenTextarea, CSS transition, React render cycle) simultaneously.
