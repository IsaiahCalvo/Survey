<hypothesis>
ROOT CAUSE (high confidence): When text wraps, the committed annotation has a LARGER HEIGHT
than the original. The SVG renderer computes the rotation center as:
  `rotate(angle, left + width/2, top + height/2)`

When height increases, `top + height/2` moves down, shifting the rotation center.
Rotating around a different center shifts the entire visual position of the annotation.

THE FIX: After committing a rotated text with changed height, compensate left/top so the
visual center (after rotation) stays at the same screen position. Concretely:

1. Compute original rotation center: `(origLeft + origW/2, origTop + origH/2)`
2. Compute new rotation center: `(newLeft + newW/2, newTop + newH/2)`
3. If they differ, adjust left/top to compensate:
   - The point that was at the original rotation center after rotation should still be at
     the same screen position after the new rotation
   - This requires solving: `rotate(angle, cx_new, cy_new) × (left, top) = rotate(angle, cx_old, cy_old) × (left, top)`

Simpler approach: Keep the rotation center fixed at the ORIGINAL center. Adjust left/top
so that `left + newH/2 = origLeft + origH/2` → `left = origLeft + (origH - newH)/2`.
Wait, that only works for the Y center. Need to think about both axes.

Actually, the simplest fix: in the commit function, when height changes for a rotated text,
adjust top so the rotation center Y stays the same:
  `json.top = origTop + (origH - newH) / 2`
And width shouldn't change (wrapping width stays constant), so X center stays the same.

Alternative: Store originX/originY='center' and use center-based coordinates.
</hypothesis>
