<!-- Screenshot naming convention -->
Filename: step-NN_MMMMMms_timing-description.png
Regex: /^step-(\d{2})_(\d+)ms_(\w+)-(.+)\.png$/
Timing values: 'baseline', 'before', 'after'

<!-- Manifest schema (relevant fields) -->
```json
{
  "scenario": "zoom-flicker",
  "result": "pass",
  "startTime": "2026-03-13T04:07:42.432Z",
  "endTime": "2026-03-13T04:07:46.901Z",
  "captureStartMs": 13474.3,
  "criteriaResults": { ... },
  "artifacts": [{ "type": "screenshot", "path": "step-01_14789ms_after-zoom-100pct.png" }, ...]
}
```

<!-- Timeline entry structure (merged) -->
State entries have: sessionMs, step, action, zoomLevel, renderedScale, targetScale, freezeState, canvasContainerCount, pageStatus, mutations, signals
Performance entries have: sessionMs, type ('cdp'|'mark'), name (for marks), detail (for marks), metrics (for CDP)
Console entries have: sessionMs, level, text, location, stackTrace

  <name>Task 1: Visual diff generation with pixelmatch</name>
  <files>

  <behavior>
    - Test: generateDiffs() finds before/after pairs by step number and produces diff images in diffs/ directory
    - Test: Each diff result includes step, before filename, after filename, diffImage path, mismatchCount, mismatchPct, totalPixels
    - Test: summary.json written to diffs/ directory with all results
    - Test: Mismatched dimensions produce error entry (not crash) with error='dimension_mismatch'
    - Test: Steps with only baseline (step 0) or only before/only after are skipped gracefully
  </behavior>
  <action>
    1. Create `debug/lib/visual-diff.mjs`:
       - Import pngjs PNG, node:fs, node:path, and pixelmatch via CJS interop (`createRequire` pattern from RESEARCH.md -- pixelmatch 4.0.2 is CJS)
       - Export `parseScreenshotName(filename)`: Parse `step-NN_MMMMMms_timing-description.png` using regex `/^step-(\d{2})_(\d+)ms_(\w+)-(.+)\.png$/`. Return { step, sessionMs, timing, description } or null.
       - Export `async generateDiffs(sessionDir)`:
         a. Create `diffs/` subdirectory in sessionDir (mkdirSync recursive)
         b. Read all .png files from sessionDir, parse each filename
         c. Group by step number, find before/after pairs (matching step number, timing='before' and timing='after')
         d. For each pair: read both PNGs with `PNG.sync.read()`, check dimension match. If mismatch, record error entry and continue.
         e. Run pixelmatch with options `{ threshold: 0.1, includeAA: false }` (anti-aliasing excluded for cleaner diffs)
         f. Write diff image as `step-NN_diff.png` in diffs/ directory using `PNG.sync.write()`
         g. Calculate mismatch percentage: `(mismatchCount / (width * height) * 100).toFixed(2)`
         h. Collect results array with: step, before, after, diffImage, mismatchCount, mismatchPct (as Number), totalPixels
         i. Write `diffs/summary.json` with results array
         j. Return results array

    2. Create `tests/visual-diff.test.mjs`:
       - Use node:test + node:assert/strict
       - Import generateDiffs and parseScreenshotName from `../debug/lib/visual-diff.mjs`
       - For image tests: use pngjs to generate tiny synthetic PNGs (e.g., 4x4 pixels) in a temp directory. Create before/after pairs where one pixel differs to produce a known mismatch count.
       - Test parseScreenshotName with valid and invalid filenames
       - Test generateDiffs against a temp session directory with synthetic PNG pairs
       - Test dimension mismatch handling
       - Test graceful handling of step-0 baseline (no pair expected)
       - Clean up temp directories in test teardown
  </action>

       - Read `diffs/summary.json` from sessionDir if it exists (for diff mismatch references in narrative)

       Structure per CONTEXT.md locked decisions (phased narrative):

       a) **Session summary header** (3-5 lines):
          - `# Session Report: {scenario}`
          - Result (PASS/FAIL), duration (endTime - startTime in ms), anomaly counts by severity
          - 1-2 sentence verdict: critical count > 0 -> "Session contains critical anomalies requiring investigation.", warnings only -> "Session completed with warnings -- review recommended.", clean -> "Session completed cleanly with no anomalies detected."

       b) **Per-step sections**:
          - Group timeline entries by `step` field (state entries have step; performance/console entries need to be assigned to the step whose time range they fall within)
          - Step time range: from the step's before-screenshot sessionMs to the next step's before-screenshot sessionMs (or session end)
          - Heading: `## Step {N}: {action} ({startMs}ms - {endMs}ms, {duration}ms)`
          - Synthesized summary: describe what happened in plain English ("Zoomed from 50% to 100%", "Annotations re-rendered on page 6")
          - Key events as bullet points with sessionMs timestamps
          - **Noise collapsing**: If > 3 DOM mutations for the same page within a step, summarize as "Page {N} destroyed/recreated {count} times over {span}ms" instead of listing each one
          - **Anomaly callouts inline**: For each anomaly whose sessionMs falls within the step's time range, insert a callout block:
            `> **{SEVERITY}** {type}: {detail} (see {screenshot ref})`

       c) **CDP metrics as step-boundary deltas**:
          - Find CDP entries at step start and end boundaries
          - Calculate deltas for LayoutCount, TaskDuration, RecalcStyleCount
          - Only display when LayoutCount delta > 20 OR TaskDuration delta > 0.1 (100ms)
          - Format as a small table or inline text under the step section

       d) **Visual diff references**: If diffs/summary.json exists, include mismatch percentage for the step's diff image when mismatchPct > 1.0 (below 1% is noise per RESEARCH.md recommendation).

         a. Read `manifest.json` from sessionDir, parse as JSON

         c. Call `detectAnomalies(timeline, manifest)` -> write `anomalies.json` to sessionDir

         e. Call `writeNarrative(timeline, anomalies, manifest, sessionDir)` -> write `timeline.md` to sessionDir
         f. Log summary: "Post-processing complete: {timeline entries} events, {anomalies} anomalies, {diffs} diffs"
         g. Return { timeline, anomalies, diffs }
       - Add CLI execution block at bottom (runs when file is executed directly):
         ```javascript
         // CLI entry point
         const isMain = process.argv[1] && (
           process.argv[1].endsWith('post-process.mjs') ||
           process.argv[1].includes('post-process')
         );
         if (isMain) {
           const sessionDir = process.argv[2];
           if (!sessionDir) {
             console.error('Usage: node debug/lib/post-process.mjs <session-dir>');
             process.exit(1);
           }
           const resolved = path.resolve(sessionDir);
           processSession(resolved).then(() => {
             console.log('Done.');
           }).catch(err => {
             console.error('Post-processing failed:', err.message);
             process.exit(1);
           });
         }
         ```
