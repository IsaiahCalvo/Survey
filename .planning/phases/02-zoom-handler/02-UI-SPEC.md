# Phase 2 — UI Design Contract

> Visual and interaction contract for the Zoom Handler phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Classification

**Phase type:** Programmatic DOM manipulation (no user-facing UI components)

This phase applies CSS transforms to overlay divs via JavaScript during zoom operations. There are no new buttons, forms, modals, text, or interactive UI elements. The overlay divs are empty in Phase 2 (content moves in during Phase 3). All "visual" output is CSS property changes on existing DOM nodes.

Traditional UI-SPEC categories (spacing scale, typography, color palette, copywriting, registry) are NOT APPLICABLE to this phase. The design contract below specifies the exact CSS properties, values, and timing that constitute the visual contract.

## CSS Transform Contract

These are the exact CSS properties and values the executor must apply. No deviation.

### During Zoom (active transform state)

| Property | Value | Applied to | When |
|----------|-------|------------|------|
| `transform` | `scale({ratio})` where `ratio = newScale / baseScale` | Each overlay div in `overlayDivsRef` where `div.isConnected === true` | Every zoom event from any of the 3 active entry points |
| `transform-origin` | `top left` | Same overlay divs | Same timing as transform |
| `pointer-events` | `none` | Same overlay divs | Already `none` from Phase 1 baseline; reinforced during zoom |

### After Settle (transform cleared)

| Property | Value | Applied to | When |
|----------|-------|------------|------|
| `transform` | `''` (empty string, removes property) | All overlay divs in `overlayDivsRef` where `div.isConnected === true` | 1000ms after last zoom event (debounce settle) |
| `transform-origin` | `''` (empty string, removes property) | Same overlay divs | Same timing |
| `pointer-events` | `none` | Same overlay divs | Remains `none` (Phase 1 baseline unchanged) |

### Base Scale Capture

| Rule | Value |
|------|-------|
| Capture timing | On FIRST zoom event of a sequence only (when `overlayZoomActiveRef.current === false`) |
| Value source | Current scale at time of first zoom event |
| Guard | `overlayZoomActiveRef` boolean ref -- set `true` on first event, reset `false` on settle |
| Recapture prevention | Do NOT update base scale on subsequent zoom events within the same sequence |

---

## Timing Contract

| Timer | Duration | Behavior |
|-------|----------|----------|
| Settle timer | 1000ms | Standard debounce: reset on each new zoom event, fires 1000ms after last event |
| Safety timeout | 5000ms | Forcibly clears all transforms if settle timer fails to fire (error recovery) |

**Rationale:** 1000ms settle is per CONTEXT.md locked decision (replaces the old 3000ms confirm-pending timer). Safety timeout is a fallback per RESEARCH.md Pitfall 2.

## Interaction Contract

### Zoom Entry Points (where transform logic executes)

| Entry Point | Location | Action Required |
|-------------|----------|-----------------|
| `handleSyncfusionZoomChange` | App.jsx ~line 12375 | MUST modify: add `applyOverlayZoomTransform(nextScale)` + `startOverlayZoomSettleTimer()` |
| Keyboard/toolbar handler | App.jsx ~line 21204 | SHOULD modify: add pre-activation of `overlayZoomActiveRef` + `overlayZoomBaseScaleRef` + `startOverlayZoomSettleTimer()` |
| Ctrl+key handler | App.jsx ~line 21691 | SHOULD modify: add pre-activation of `overlayZoomActiveRef` + `overlayZoomBaseScaleRef` + `startOverlayZoomSettleTimer()` |
| Finalize-idle handler | App.jsx ~line 10663 | NO CHANGE: operates on old system only |

**Source:** RESEARCH.md zoom entry point analysis.

### Zoom Methods Covered

All 6 zoom methods must produce the same visual behavior (overlay divs scale with CSS transform during zoom, transforms removed after settle):

| Method | Entry Point Flow | Automatable |
|--------|-----------------|-------------|
| Ctrl+scroll wheel | handleSyncfusionZoomChange | Yes (Playwright wheel event) |
| Toolbar zoom buttons | Keyboard/toolbar handler -> handleSyncfusionZoomChange | Yes (Playwright click) |
| Zoom percentage dropdown | handleSyncfusionZoomChange | Yes (Playwright click) |
| Fit-to-page | handleSyncfusionZoomChange | Yes (Playwright click) |
| Fit-to-width | handleSyncfusionZoomChange | Yes (Playwright click) |
| Pinch-to-zoom (trackpad) | Ctrl+scroll path -> handleSyncfusionZoomChange | No (manual only) |

### Pointer Event Behavior

| State | Overlay div `pointer-events` | PAL canvas `pointer-events` |
|-------|-----------------------------|-----------------------------|
| Idle (no zoom) | `none` (Phase 1 baseline) | Managed by PAL internally (unchanged) |
| Active zoom | `none` (reinforced) | Managed by PAL internally (unchanged) |
| After settle | `none` (Phase 1 baseline) | Managed by PAL internally (unchanged) |

**Note:** No pointer event conflict exists in Phase 2 because PAL canvas lives in the old portal system (`syncfusionStablePortalHostsRef`), not inside overlay divs. Conflict is not possible until Phase 3.

## DOM Node Filtering Contract

| Rule | Implementation |
|------|---------------|
| Apply transforms to | Only overlay divs where `div.isConnected === true` |
| Skip transforms for | Overlay divs detached from DOM (Syncfusion destroyed parent page div) |
| Guard pattern | `if (div && div.isConnected)` before every style write |
| Performance rationale | Avoids wasted DOM style writes on disconnected nodes |

**Source:** RESEARCH.md Pitfall 3.

## Coexistence Contract (old system parallel operation)

| Rule | Detail |
|------|--------|
| DO NOT modify | `syncfusionOverlayContentRefs` nodes |
| DO NOT modify | `syncfusionStablePortalHostsRef` nodes |
| DO NOT remove | Any freeze/snapshot/confirm-pending code (Phase 6 work) |
| New system operates on | `overlayDivsRef` nodes exclusively |
| Old system operates on | `syncfusionOverlayContentRefs` / `syncfusionStablePortalHostsRef` exclusively |
| Timer duration | Both systems use 1000ms settle timer so they settle approximately together |

**Source:** CONTEXT.md locked decision on coexistence.
