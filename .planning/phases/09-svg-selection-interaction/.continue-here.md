- **Pan blocked by SVG wrapper div** — FIXED. Wrapper div had `pointerEvents: 'auto'` + `stopPropagation` always-on, blocking Syncfusion. Changed to conditional: `'auto'` only for select/text-select, `'none'` for all other tools.
- **Syncfusion SVGAnimatedString crash** — FIXED. `pdfviewer-base.js` crashed on `target.className.indexOf` when events hit SVG elements. Solution: wrapper div stopPropagation only in select mode, preventing SVG events from reaching Syncfusion.
- **SVG captured events during pan** — FIXED. Removed `'pan'` from `isInteractive` list in SVGAnnotationLayer. Only `'select'` and `'text-select'` are interactive now.
- **Path hit rects at (0,0,0,0)** — FIXED. Imported PDF path annotations have NO `left`/`top`/`width`/`height`/`scaleX`/`scaleY`/`pathOffset` properties. Added path-data scanning in `getPathBBox()` to compute bbox from actual `M/C/L/Z` command coordinates.
- **CSS `pointerEvents: 'fill'` unreliable** — FIXED. Changed hit rects from `style={{ pointerEvents: 'fill' }}` to SVG attribute `pointerEvents="all"`.
- Debug visualization (red hit rects) added then removed after confirming alignment.
</completed_work>

<decisions_made>

- Wrapper div `pointerEvents` is tool-dependent: `'auto'` + `stopPropagation` for select/text-select, `'none'` for everything else. Both SVGAnnotationLayer instances in App.jsx updated.
- Hit rect uses SVG attribute `pointerEvents="all"` instead of CSS `style={{ pointerEvents: 'fill' }}` — more reliable cross-browser.
- `getPathBBox` now has two code paths: standard Fabric.js objects (use left/top/width/height with center-origin offset), and imported PDF paths (scan path commands for min/max coordinates).
- Center-origin bbox for standard Fabric.js paths: `left = obj.left - scaledWidth/2, top = obj.top - scaledHeight/2` (because pathOffset transform centers the path at left,top).
</decisions_made>

<blockers>
- Imported PDF path annotations have fundamentally different data model (absolute path coordinates, no left/top/width/height/scaleX/scaleY). All interaction code in `useSVGInteraction.js` assumes Fabric.js properties exist. This needs a compatibility layer or path-coordinate-aware move/resize logic.
</blockers>

<context>
The core problem was that Phase 9 Plans 01-03 built selection/drag/resize assuming standard Fabric.js JSON properties. But the actual PDF annotations are imported from Adobe/other tools and only have `type`, `path` (absolute coords), `stroke`, `strokeWidth`, `fill`, and metadata flags. No positioning properties at all.

The fix strategy for drag/resize should be: compute bbox from path data (already done in getPathBBox), then on save, translate all path coordinates by the drag delta (for move) or scale all coordinates around the bbox center (for resize). This avoids needing to add synthetic Fabric.js properties.
</context>
