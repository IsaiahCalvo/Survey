## 🟠 THE BIGGEST REAL BUG — annotation data loss on page operations

Confirmed in code: the page tools (delete / duplicate / insert / paste /
reorder) never tell the annotation layer that pages moved.

- On **local (not-yet-cloud) files**, any page operation changes the file's
  identity and **wipes all annotations** — irreversible.
- On **all files**, annotations stay glued to old page numbers and render on the
  **wrong page** after a delete/insert.
- **Reorder** only renames pages; it doesn't actually move them.
- **Insert-blank-page** isn't reachable from the thumbnail menu.

Fix (planned next, fully unit-testable offline): a pure page-key reindex helper
wired into each page handler, a stable per-document id for local files, and real
reorder. The reindex logic can be proven with tests; the final carry-over is
best confirmed by you exercising a page delete on a local file.

## 🟡 OTHER VERIFIED RISKS (ranked)

- **Excel two-way sync is last-write-wins** — a collaborator's direct edits in
  the ~5-second push window get silently overwritten (no change-conflict check).
- **Microsoft/OneDrive tokens are stored unencrypted** in the database (full
  OneDrive+SharePoint scope); exploit needs a DB leak, but encrypt them at rest.
- **Shared-document deletes for callouts aren't enforced on the server** for the
  live collaboration path — an editor collaborator can delete another user's
  callouts. (Survey markers ARE protected — verified.)
- **Survey-marker deletes can cascade** on a brief empty-state race (owner
  session can wipe everyone's markers).
- **Electron is end-of-life** (years of unpatched browser fixes) and **pdf.js is
  two majors behind** — both are dedicated, owner-tested upgrades.
- **The stamp tool renders/exports nothing** — decide if it's in scope.
