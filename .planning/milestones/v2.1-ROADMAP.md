## Overview

Finish the shape editing interaction model started in the post-v2.0 cleanup
branch — add rotation precision (soft Shift-snap at 45° + exact-value typed
angles) and extend the usable zoom range down to 10% so shape editing feels
complete before moving on to v2.2+ foundation wins.

v2.2+ per user Option A. The three core requirements (EDIT-11, EDIT-12,
ZOOM-09) shipped with 113/113 tests green and user-confirmed "100% approved"
on the typed-rotation commit path.

## Phases

### Phase 12: Shape Edit Polish

**Goal**: Shape rotation feels precise and predictable (soft Shift-snap to
45° when the user is near an increment, exact-value input for typed angles)
and the usable zoom range extends down to 10% for whole-page inspection of
mechanical/electrical drawings.

**Depends on**: Phase 11 (SVG selection + `useSVGInteraction` rotation path,
`FabricEditCanvas` edit infrastructure, zero-timer zoom system)

**Requirements**: EDIT-11, EDIT-12, ZOOM-09

**Success Criteria** (from 12-CONTEXT.md):

1. User can drag the SVG rotation handle on a selected shape with Shift held
   and the live angle soft-snaps to the nearest 45° increment
   (0°/45°/90°/135°/180°/225°/270°/315°) only when within 3° of that
   increment — Shift-at-41° stays free at 41°, Shift-at-44° snaps to 45°,
   Shift-at-23° stays free at 23°, and releasing Shift always returns to
   free rotation.
2. User sees an inline numeric degree input near the rotation handle while
   rotating a selected shape (and/or hovering the rotation handle), can type
   an exact angle, commits with Enter or blur to apply the rotation
   atomically, cancels with Escape, and typed values are normalized to
   `[0, 360)` before persisting.
3. User can zoom the PDF all the way down to 10% via every zoom entry point
   (toolbar buttons, keyboard shortcuts, scroll wheel, typed value in the
   zoom input box, fit-to-page, fit-to-width, pinch) without the app
   silently re-clamping the floor to 50%.
4. At zoom levels below 25% the selection/rotation handles remain visible
   but become hard to target — accepted table-stakes behavior (matches
   Illustrator/Photoshop); the user is expected to zoom back in to edit and
   no defect is recorded.
5. No existing behavior regresses: free rotation (Shift not held) still
   produces float angles, Shift+resize aspect-lock still works, every zoom
   method still funnels through `clampScale`, and the `zoomGeneration`
   signal contract is preserved.

**Details:**

The milestone delivered the three planned v2.1 requirements with a
significant scope expansion in Plan 12-01 (9 dual-path gap bugs folded in
during verification) and an unplanned gap-closure plan (12-03) authored
mid-phase after 12-02 UAT surfaced a commit-latency blocker on the typed
rotation path.

The canonical architectural lesson from Phase 12 is the drag-rotate
**optimistic-paint pattern**: paint cheap `visualTransform.rotate` first,
dispatch heavy `onSaveAnnotations` second. This pattern is now the reusable
fix for any commit-path latency in the SVG annotation layer and is
documented inline in `useSVGInteraction.js:835-888` with `SIDE EFFECT` +
`drag-wins invariant` JSDoc grep markers.

A second load-bearing lesson: **on portaled UI inside an interactive SVG
layer, stop the FULL click cycle (mouseDown + mouseUp + click + pointerDown
+ pointerUp) at the wrapper boundary, not just the down events**. Round 7
of Plan 12-02's focus-loss hunt produced a ~3-line fix after 6 wrong
hypotheses.

**Counter-session lane discipline held clean through the entire milestone.**
A parallel counter-tool session ran in the same working tree during v2.1,
producing uncommitted WIP in `src/App.jsx`, `src/PageAnnotationLayer.jsx`,
`src/components/FabricEditCanvas.jsx`, `src/hooks/useDatabase.js`,
`src/utils/counterNumbering.js`, `src/utils/svgAnnotationRenderers.jsx`,
and `dist/index.html`. Phase 12 never staged, edited, or enumerated these
files as commit candidates — the feedback rule `feedback_no_rotation_input_field.md`
isolated the lanes successfully.

## Milestone Summary

**Decimal Phases:** None. Phase 12 was the only phase in v2.1.

**Key Decisions:**

- EDIT-11 shipped as a pure `snapAngleToNearest45(angle, threshold = 3)`
  helper + one-line wire into the rotate branch (mirrors Fabric's
  `snapThreshold` convention). Soft snap only applies when the free angle
  is within 3° of an increment; Shift-at-41° stays free at 41°.

- ZOOM-09 shipped as an atomic 2-file commit (`df43b0f8`). The
  `zoomController.js:15` MIN_SCALE constant and `App.jsx:21999`
  `commitZoomInput` pre-clamp cannot be split without producing a broken
  intermediate state where zoom input typed "10" silently re-clamps to 50.

- EDIT-12 was a deliberate **scope expansion** from the original ~11-LOC
  backlog estimate to a 1,195-LOC rotation input field feature. Approved
  during `/gsd:discuss-phase`. Architecture locked to HTML portal (not
  foreignObject or SVG sibling) to avoid IME/focus quirks and counter-rotation
  math. Input is uncontrolled (defaultValue + ref) after Rounds 5/6 proved
  a controlled input racing live drag updates swallowed keystrokes.

- Pill orbit radius is constant across all rotations using a worst-case
  AABB projection from shape center: `EXTENSION = max(handleW,handleH)/2 +
  gap + max(pillW,pillH)/2`. User's invariant is "distance from shape =
  constant", not "edge-to-edge gap = constant."

- Typed-value commits NEVER apply Shift-snap. Snap is a drag-only gesture
  modifier. Typing 44 with Shift held still commits 44°.

- Plan 12-03 was spun as an **unplanned gap-closure plan** mid-phase when
  12-02 UAT surfaced Gap 1 (Enter-commit lag). Authored, executed, and
  closed inside the same phase rather than deferred. Without 12-03, EDIT-12
  would have shipped broken on the most common user path.

- Plan 12-01 was expanded in-flight to include 9 dual-path shape edit gap
  bugs rather than deferring them to v2.2. Kept the dual-path SVG↔Fabric
  edit model landing coherent in one plan.

- Gap 4 investigation (rotation handle clipped when pre-rotated shape
  enters edit mode) was explicitly OUT of scope for Phase 12 — suspect is
  `FabricEditCanvas` container `overflow: hidden` / clip-path, filed in
  `FEATURE-BACKLOG.md` Stage 0 for v2.2+.

- Phase closed via **Option A** (close phase, backlog 2 polish gaps) rather
  than Option B (hold phase open until gaps close). User decision preserved
  in `12-VERIFICATION.md` `human_decision` annotation for audit trail.

**Issues Resolved:**

- Commit-path latency on typed-value rotation commits (Enter + Arrow ±1°)
  felt laggy vs drag-rotate — fixed by `applyOptimisticRotation` helper in
  Plan 12-03.
- RotationInputField text-input focus-loss on mouseup after 7 rounds of
  debugging (Rounds 1–6 chased wrong hypotheses: capture-phase preventDefault,
  controlled-input race, parent re-render remount, programmatic .focus(),
  nativeEvent stopImmediatePropagation). Root cause: wrapper had `onMouseDown`
  + `onPointerDown` stopPropagation but NOT `onMouseUp` / `onPointerUp` /
  `onClick` — the full click cycle leaked to a parent handler that caused
  focus loss.
- Keystrokes swallowed on RotationInputField digit input — caused by
  `e.nativeEvent.stopImmediatePropagation()` on React `onKeyDown` interfering
  with the browser's text-input pipeline. Fix: remove `nativeEvent` call,
  use only synthetic `e.stopPropagation()`.
- Stale EDIT-11 and ZOOM-09 checkboxes in REQUIREMENTS.md traceability table
  (implementation shipped in 12-01 at commit `df43b0f8` but `gsd-tools` CLI
  didn't auto-flip because Plan 12-01's frontmatter `requirements:` was
  incomplete). Flipped during reconciliation.
- Dual-path shape edit parity: 9 gap bugs fixed for rect/circle/ellipse
  across scale, flip, mini-bar tracking, fit-page math, handle clip, and
  first-time circle jump.
- Fit-page / fit-height using the Syncfusion-reported zoom percentage was
  unreliable under Electron's 1.33 factor — now computed from pdf.js
  `pageSize` multiplied by the calibrated Electron device factor.

**Issues Deferred (v2.2+):**

- **Gap 3** — Rotation pill doesn't reappear on hover after returning from
  edit mode via click-off. Suspect: hover-intent effect in
  `SVGAnnotationLayer.jsx` has stale `handleEl` ref after React reconciles
  the overlay post-edit-commit. Workaround: full deselect + reselect.
  Filed in `FEATURE-BACKLOG.md` Stage 0.

- **Gap 4** — Rotation handle (mtr) clipped when a pre-rotated shape enters
  edit mode. Suspect: `FabricEditCanvas` container `overflow: hidden` or
  tight clip-path cuts off mtr handle geometry. Does NOT happen at 0°.
  Filed in `FEATURE-BACKLOG.md` Stage 0.

- **Gap 2** — Rotation pill off-screen when rotation handle is off-screen
  (feature request, not a defect). Filed in `FEATURE-BACKLOG.md` Stage 0.

- **Blur-commit and invalid-value revert** (EDIT-12 AC #7 + #8) — user
  explicitly de-scoped during 12-02 UAT ("no but thats fine, i dont want
  that"). Pill commits on Enter, reverts on Escape, and blur is treated as
  "no change." Documented in `12-02-SUMMARY.md` as intentional de-scope.

- **Phase 7 widen zoom range** beyond 500% — deferred from v1.0, still
  backlogged.

**Technical Debt Incurred:**

- Diagnostic scaffolding (lifecycle logs, focusout listener, input event
  tracker, identity tracker) remains in `RotationInputField.jsx` under
  `LOG=false`. Inert at runtime but adds ~80 LOC of log plumbing. Stripping
  is optional cleanup, not blocking.

- `App.jsx:21999` → `App.jsx:22441` line number drift caused by the
  uncommitted counter-session WIP. The `Math.max(parsed, 10)` token itself
  is intact but the line number in 12-01-SUMMARY is stale. Will stabilize
  once counter-session commits its WIP.

- Plan 12-01's frontmatter `requirements:` field didn't list EDIT-11 and
  ZOOM-09, so `gsd-tools state advance-plan` didn't auto-flip those
  checkboxes at plan close. Minor GSD tooling nit filed in reconciliation
  Lesson 7 — no action item here.
