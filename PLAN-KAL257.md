## Key decisions & tradeoffs
- **Dedicated cloud test project vs production:** tests INSERT rows and the charter forbids prod writes; survey-test is disposable and free-tier. Tradeoff: its schema is bootstrap-maintained, not migration-maintained — drift is possible; mitigated by bootstrapping the phase27 DDL verbatim from the committed migration and pinning shapes in `schemaPresence`.
- **Bootstrap script vs repairing the migration chain:** adding a synthetic "baseline" migration would alter the prod migration story overnight — out of bounds. Chain-repair filed as a finding instead.
- **Introspection view vs migration:** the view is test-infra; shipping it to prod via a migration would be wrong. It lives in the bootstrap script, test-project-only.
- **Fixing the tests' query path + FK setup vs leaving as-written:** as-written they fail the moment the env var is set, so "un-skip" without fixes would be a lie. Assertions unchanged; only the transport (view) and test hygiene (parent row) change.
- **§2.3 honesty:** no hollow green — a corrected fixme + precise blocker beats a test that asserts nothing real.
