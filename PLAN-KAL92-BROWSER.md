## Goal

Close KAL-92's open acceptance bullets with a browser-level regression harness driving the real mounted app, proving:

1. **(stale-smaller CRDT vs rendered durable truth — the incident shape)** when the phase30 Y.Map is smaller than the rendered annotation state and a `crdt:dedupe-resync` arrives, the guard refuses, nothing disappears from the DOM, zero destructive backend calls are issued, and the pinned `dedupe-resync skipped unsafe shrink` signature logs with `reason:"startup-shrink"`;
2. **(survey markers survive open + hydration)** survey markers seeded in the durable Y.Doc render (after selecting their module) and are never deleted during/after hydration;
3. **(idle invariant)** 16s+ of idle plus focus/online events changes nothing: DOM counts stable, no mutating call beyond the expected whitelist;
4. **(falsification control)** the same listener genuinely applies a resync when the guard allows it: on a second fixture doc whose Y.Map is *larger* than rendered state, the dispatched event grows the DOM count and logs `dedupe-resync — restoring state` — proving scenario 1's pass is not a dead listener or a blind assertion.

## Architecture

New `agent-cli/regress-idle-disappearance.mjs` + `agent-cli/lib/supabaseMock.mjs` (route router, PostgREST semantics, fixture store, ledgers) + `agent-cli/lib/kal92Fixtures.mjs` (WAL builder using the app's own annotationDocStore via Node ESM import; document/annotation/template row factories). Established agent-cli idioms throughout (chromium launch, console+pageerror capture before goto, HEADFUL toggle, exit 0/1/2, failure screenshots).

**Server:** spawn `npx vite --port 5199 --strictPort` (normal `.env`/`.env.local`; killed in `finally`). Readiness = poll HTTP 200. Does not touch Isaiah's :5173.

**Network edge (safety core):**
- `**/rest/v1/**` and `**/storage/v1/**`: handled entirely by the router; `route.continue()` is structurally unreachable for these patterns → production DB/storage writes impossible by construction. Mutations are recorded to a `mutations[]` ledger (method, table, parsed filters, body) and answered with PostgREST-correct synthetic success. Reads answered from fixtures honoring the actual query params.
- **Unmatched policy (revised per Codex):** any request the router doesn't recognize is recorded and answered with a PostgREST-shaped **error** (500 + error body), and the run FAILS at verdict time — no silent 200-empty fake-success paths.
- **Storage discrimination (revised per Codex):** fixture PDF bytes ONLY for the seeded `file_path`; `*_data.json` sidecar pattern → 404 (path is skipped for cloud docs anyway); anything else → 404 + recorded.
- `/auth/v1/**` passes through (real dev-account login — daily agent-cli practice). `/realtime/v1/**` passes through; **the no-write claim is explicitly scoped to DB REST + storage** (revised per Codex): realtime traffic is ephemeral broadcast/presence on channels keyed to a fabricated doc UUID nobody else subscribes to; postgres_changes deliver nothing (no real rows). Fabricated UUID also means even an escaped write would fail FK in production.
- **Expected-mutation whitelist (revised per Codex r1+r2):** `document_presence` upserts/deletes, `documents` UPDATE (`last_opened_at`, `tool_preferences`, `cutover_completed_at` from backfill), `document_history_events` upserts, **idempotent survey-marker UPSERTs to `document_annotations` whose `annotation_id`s are a subset of the seeded marker ids** (the post-hydrate marker projection sync may re-upsert; a DELETE or an upsert batch missing seeded ids is still a violation), and (DOC-B post-apply window only) `annotation_updates` INSERTs + debounced `annotation_snapshots` upserts. **`doc_yjs_state` writes are disallowed everywhere** (revised per Codex r3: its only writer is the legacy snapshot path inside the disabled hydrate hook — a `doc_yjs_state` write appearing at all is a regression signal). Everything else mutating = destructive = fail.
- **Scenario-scoped ledgers (revised per Codex r2):** each scenario gets its own assertion window with a settle/drain wait before the window closes (debounced writers flush), and teardown writes after the final assertion window are recorded but not asserted against. Prevents DOC-B's late snapshot debounce from leaking into S2's strict window.
- **Idle-window strictness:** during S2 the whitelist tightens — zero `annotation_updates`/`annotation_snapshots`/`doc_yjs_state` writes at all (subsumes Codex's "Yjs updates can encode destructive clears without DELETE": no WAL writes during idle means no encoded clears).

**Fixtures — two documents, all content on PAGE 1 (revised per Codex: DOM selectors only count rendered pages):**
- **DOC-A (guard case / incident shape):** WAL = 12 fabric annotations + 5 survey markers (`surveyMarkers` map, `moduleId` = fixture module). `document_annotations` = ONLY the 5 survey-marker rows in **marker-only mapper shape — no `annotation_data.fabricObject`** (revised per Codex r2; matches documentSurveyMarkerMapper.js and avoids the legacy fabric-row drop filter reading them ambiguously) ⇒ non-backfillable ⇒ phase30 Y.Map = 0 after backfill ⇒ genuinely stale-smaller CRDT vs 12 rendered.
- **DOC-B (growth control):** WAL = 4 fabric annotations. `document_annotations` = 12 geometrically-distinct backfillable fabric rows ⇒ Y.Map = 12 > rendered 4.
- One `documents` row each (fabricated UUIDs, `user_id` echoed from the dashboard query's own `user_id=eq.` param, `archived:false`, `cutover_completed_at:null`, **`embedded_import_completed_at` set non-null** (revised per Codex r2: blocks the embedded-PDF import path so se011.pdf's native annotations can't contaminate counts or the WAL, and removes that documents-UPDATE from the expected set), `file_path` → fixture PDF `debug/fixtures/se011.pdf`). `templates` fixture with one template + module matching marker `moduleId`. **`user_subscriptions` → maybeSingle returns an ACTIVE `{tier:'pro', status:'active'}` row** (revised per Codex r2 — verified: `advancedSurvey` requires pro/enterprise/developer, AuthContext.jsx:553; free tier would dead-end the survey assertions behind the upgrade alert at PDFViewer.jsx:4698); the storage probe `.single()` returns `{storage_used_bytes:0}`. Counts via `Content-Range`. **`annotation_updates` client_seq seed query** (`select client_seq … eq client_id … order client_seq desc limit 1`) explicitly routed (revised per Codex r2).
- **Step 1 of implementation is a discovery run through the SAME router with the minimal best-guess fixtures** (revised per Codex r3: a fixtureless record-only run can't get past login/dashboard without forwarding, which is forbidden) — every unmatched request is logged with its full shape and fails the run; iterate fixtures until the open→idle flow completes with `unmatched[]` empty. The enforcement stays on permanently.

**Instrumentation:** `addInitScript`: `window.__CLOUD_SYNC_DEBUG = true` (skip/restore signatures are console.debug behind it). Sync points: painted canvas; `g[data-annotation-index]` count; `[data-survey-marker-id]` count; `window.__crdtBackfillDone` with timeout fallback.

## Scenarios

**S0 — open DOC-A + hydrate baseline.** Login → dashboard → open DOC-A. Await paint + `__crdtBackfillDone`. **Sequenced visibility assertions (revised per Codex r3 — survey-module selection can scope-hide non-survey annotations):** (a) survey panel CLOSED: assert 12 `data-annotation-index` elements on page 1; (b) activate survey via the right-rail toggle → **template-selection modal → click the fixture template → click the fixture module** (revised per Codex r2: survey activation goes through `showTemplateSelection`, PDFViewer.jsx:4703/31548), assert 5 `[data-survey-marker-id]`; (c) close the survey panel and re-assert 12 fabric elements before S1. Ledger shows no destructive mutations (covers "survey markers not deleted during pending cloud hydration" — that window elapsed during this open; idempotent marker re-upserts containing all seeded ids are whitelisted, DELETE/missing-id batches fail).

**S1 — unsafe shrink refused.** Dispatch `window.dispatchEvent(new CustomEvent('crdt:dedupe-resync', {detail:{documentId:DOC_A, removed:1}}))`. Expected deterministically: `currentCount=12, resyncCount=0, shrink=12` → refusal `reason:"startup-shrink"`. Assert: exact skip signature + reason in logs; then the sequenced count check (revised per Codex r4): panel closed → 12 fabric; reopen module → 5 markers; close again. No new non-whitelisted mutations.

**S2 — idle invariant.** Wait 16s (> `RECENT_CLOUD_REFRESH_SKIP_MS`), dispatch `focus` + `online`. Honest framing: the legacy focus/online refresh paths are disabled in today's app — this is a **sentinel invariant** (if anyone re-enables them, or any live listener misbehaves, this catches the regression), not a live-path exercise. Assert via the same sequenced pattern (panel closed → 12 fabric; module open → 5 markers; close — revised per Codex r4); ZERO annotation-content writes (incl. WAL/snapshot/state tables); no unsafe-shrink or hydrate-empty-delete warn signatures.

**S3 — growth control on DOC-B (falsification).** Close DOC-A tab, open DOC-B, await backfill (Y.Map=12, rendered=4). Dispatch the same event (`removed:1`). Guard: `resyncCount=12 ≥ currentCount=4` → `not-a-shrink` → APPLIES. Assert: `dedupe-resync — restoring state` signature; `data-annotation-index` count goes 4 → 12. Proves the listener + materialize + setState path is live and the harness detects count changes — S1 cannot pass via a dead listener. (Any `annotation_updates` INSERT and debounced `annotation_snapshots` upsert triggered by the state change is expected here, must return `{seq:N}` for WAL inserts, and is allowed only in this scenario's ledger window; the window drains debounced writers before closing — revised per Codex r2/r3.)

**S4 — intentional delete propagates (best-effort).** On DOC-B, UI-delete one survey marker or fabric annotation (click + delete affordance). PASS = a `document_annotations` DELETE (and/or WAL update) lands in `mutations[]` — recorded, synthetic-200, never forwarded. If UI flake defeats this within a reasonable implementation budget, S4 ships SKIPPED-with-note (delete propagation is unit-pinned; ticket comment states which outcome shipped).

Verdict: exit 0 iff S0–S3 pass + `unmatched[]` empty (S4 per above). Failure → screenshot + filtered log tail.

## Key decisions & tradeoffs

- **Mock-at-network-edge vs survey-test cloud project:** survey-test lacks `document_annotations`, a usable `documents` schema, storage, RLS policies, an anon key, and an auth user; creating them needs the Management API token (`supabase login`) which is not on this machine, and the migration chain can't replay on a blank DB. Full-stack arm stays a documented follow-up gated on Isaiah. Zero-write-by-construction beats careful-writes for an unattended loop.
- **Synthetic event dispatch at the producer boundary:** the natural producer fires only on real PDF-import duplicates inside the phase30 Y.Doc mid-backfill; staging that via network fixtures is not worth the fidelity delta. The producer's gate+payload is unit-pinned (tests/dedupeResyncSafetyBranches.test.mjs); the browser arm proves the consumer side end-to-end with both a refusal and an applied control.
- **Growth control instead of allowed-shrink control:** `expected-dedupe-shrink` requires `hydrated:true`, which the live app can never reach with the hook disabled — an allowed-shrink control would be impossible-by-construction. Growth (`not-a-shrink`) is the apply path that exists in production today.
- **Realtime passthrough, claim narrowed to DB REST + storage:** Playwright can't route websockets meaningfully without mocking the Phoenix protocol; the broadcast traffic is ephemeral, keyed to fabricated UUIDs, and FK-protected against any hypothetical escape. Logged as an explicit scope statement, not hidden.
- **Rejected Codex simplification (skip Dashboard/auth, preload local fixture):** the value of this arm over the existing unit slice is precisely the real open path — real auth, real dashboard open flow, real YDocProvider backfill, real mounted listeners. Auth+dashboard driving is proven daily by agent-cli scripts; the cost is small.

## Risks / open questions

- **WAL fixture encoding:** `annotation_updates.data` wire format (PostgREST bytea hex vs base64) and the exact store map shapes are pinned at implementation by reading annotationDocSync/annotationDocStore and the discovery run; the fixture builder uses the app's own modules so shape drift breaks loudly at build time, not silently.
- **useAnnotationDoc reaction to S3's setState:** may push WAL INSERTs (handled: expected-window whitelist + `{seq}` responses). Verified empirically in discovery.
- **Module-click UI driving for marker visibility:** if the survey panel/module DOM proves unstable for automation, fall back to asserting marker state via the app's own console diagnostics + Y.Doc state through `page.evaluate`, and note the DOM-count limitation. DOM count remains the target.
- **`.single()` semantics:** the mock must produce PGRST116-shaped errors where the app expects them (user_subscriptions storage probe) — wrong shapes stall the dashboard. Inventory is verified; discovery run double-checks.
- **Runtime ~90s** (16s idle + two doc opens) — acceptable on-demand.
